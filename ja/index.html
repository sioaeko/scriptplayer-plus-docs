インストール

ScriptPlayer+ は GitHub Releases にある Windows・macOS・Linux 向けパッケージからインストールします。初回起動時に OS がセキュリティ警告を出すことがあるため、その対処も併せて記載しています。

ダウンロード#

すべてのビルドは GitHub Releases の最新ページで公開されます。お使いの OS に合うファイルを選んでください。

プラットフォームパッケージ備考
Windows x64 インストーラー（.exe）またはポータブル .zip インストールせずに使うなら、ポータブル ZIP を展開するだけで動きます。
macOS x64 / arm64 .dmg または .zip Apple Silicon 用と Intel 用が別にあります。お使いの機種に合うほうを選んでください。
Linux x64 .deb · AppImage · アーカイブ版 Ubuntu / Kubuntu 24.04 以降は DEB を推奨します。

Windows#

  1. インストーラーを実行する

    ダウンロードした .exe を実行すると、まず使用許諾契約（EULA）が表示されます。内容を確認して同意するとインストールが進みます。

  2. SmartScreen の警告が出たら

    Windows パッケージには Authenticode 署名が入っていないため、Microsoft Defender SmartScreen が「Windows によって PC が保護されました」のような表示を出すことがあります。詳細情報 → 実行を押すとインストールを続けられます。

  3. ポータブル ZIP を使う場合

    展開したフォルダー内の実行ファイルをそのまま起動します。設定とキャッシュはユーザーフォルダーに保存されます。

macOS#

最低バージョン

v0.6.0 から Electron ランタイムが上がり、必要な macOS の最低バージョンが Big Sur 11 から Monterey 12 になりました。Big Sur では v0.6 以降を使えません。

  1. DMG を開いてアプリを移動する

    .dmg を開き、ScriptPlayer+ のアイコンをアプリケーションフォルダーへドラッグします。

  2. 「開けません」と警告が出たら

    Gatekeeper が開発元を確認できないという警告を出すことがあります。システム設定 → プライバシーとセキュリティを開き、下に現れる「このまま開く」ボタンを押すと起動できます。

Linux#

Ubuntu / Kubuntu 24.04 以降では DEB パッケージの使用を推奨します。これらのバージョンは非特権ユーザー名前空間を制限しており、Chromium のサンドボックスが動くには実行ファイル単位の AppArmor プロファイルが必要で、それは DEB パッケージにのみ含まれています。

  • DEB — AppArmor プロファイルも一緒にインストールします。24.04 以降ではもっとも安全な選択です。
  • AppImage — v0.6.0 から静的ランタイムになり、libfuse.so.2 は不要になりました。
  • アーカイブ版 — ユーザー名前空間が利用できるディストリビューションで使えます。
サンドボックスは無効化しません

ScriptPlayer+ は、システム全体の名前空間制限に遭遇しても --no-sandbox で自動的に回避することはありません。ポータブル AppImage やアーカイブ版が起動しない場合は DEB パッケージを入れてください。

アップデート#

新しいバージョンが出るとアプリ内で通知します。通知からそのままダウンロードしてインストールでき、同じバージョン番号で出たホットフィックスも検出します。確認方法は設定 → 一般で調整します。

5分ではじめる

インストールが終わったらここからです。5つのステップで映像が再生され、スクリプトが読み込まれ、デバイスが動きます。

5つのステップ#

  1. メディアがあるフォルダーを開く

    左上の Folder ボタンを押して、映像が入っているフォルダーを選びます。1つのファイルをすぐ見たいだけなら、ウィンドウへドラッグ＆ドロップしても開けます。

  2. 一覧から映像を選ぶ

    サイドバーのファイル一覧でファイルをクリックすると、すぐ再生が始まります。ファイル名の右に緑のドキュメントアイコンがあれば、対応するファンスクリプトが見つかったという意味です。

  3. スクリプトが読み込まれたか確認する

    映像の下にヒートマップの帯とタイムラインのグラフが見えていれば、スクリプトは正しく読み込まれています。見えない場合は再生バーの HM・TL ボタンで表示してみてください。

  4. デバイスを接続する

    左レールのデバイスアイコンを押し、使うデバイスを選んで接続します。デバイスごとの詳しい設定は The Handy、Intiface、FunOSR を参照してください。

  5. 再生して強さを合わせる

    Space で再生します。動きが強すぎる・弱すぎるときは再生バーの STR でストローク範囲を狭めたり広げたりします。タイミングがずれていれば +0ms ボタンでオフセットを調整します。

先に知っておくとよいこと
  • スクリプトは通常、映像と同じフォルダーに同じ名前で置けば自動で認識されます。（映像.mp4 ↔ 映像.funscript）
  • スクリプトを別のフォルダーにまとめているなら、設定でスクリプトフォルダーとして指定しておきましょう。
  • デバイスを初めて使うときは、ストローク範囲を狭くして始めるほうが安全です。

フォルダーの代わりにライブラリを使う#

毎回フォルダーを開く代わりに、よく使うフォルダーをライブラリに登録しておけばサムネイルカードで一覧できます。左レール最下部のライブラリアイコンから始めます。詳しくはライブラリをご覧ください。

サイドバー#

ファイル画面を基準に、上から下へこう並んでいます。

  • Folder — メディアフォルダーを開きます。隣の小さなボタンでスクリプトフォルダーの指定、スクリプトの読み込み・保存、再スキャンを行います。
  • Recent Media — 最近開いたファイルの一覧です。項目横の × で1件ずつ、ごみ箱アイコンで全件消せます。
  • Filter files… — ファイル名で絞り込みます。右の数字は現在表示されているファイル数です。
  • Show multi-axis files only — 多軸スクリプトがあるファイルだけ表示します。
  • Show rated files only — 評価を付けたファイルだけ表示します。
  • 並べ替え — Path（パス）をはじめ、名前・評価・再生時間・更新日時で並べ替え、Asc/Desc で方向を変えます。
  • Script Variants — いまのメディアに合うスクリプトが複数あるときに選ぶパネルです。 → スクリプトを扱う
  • ファイル一覧 — スクリプトがあるファイルには緑のドキュメントアイコンが付きます。

再生バーのボタン辞典#

画面最下部の行です。左が再生操作、右が表示・スクリプト関連のトグルです。短い英字略号の意味は次のとおりです。

1x再生速度 — 両側の − + で速度を調整します。
STRストローク（Stroke） — デバイスが動く範囲をその場で狭めたり広げたりします。反転トグルもここにあります。
+0msスクリプトオフセット — 映像と動きの時間差を前後にずらします。-60秒 ～ +60秒の範囲で調整できます。
AB区間リピート — A地点とB地点を指定し、その間だけを繰り返し再生します。
リピート — いま再生中のファイルだけを繰り返します。次のファイルへ自動で進むのは Auto Next Play の設定です。
シャッフル — 一覧をランダムな順で再生します。
EXT外部プレーヤー（External） — mpv・VLC などの外部プレーヤーでこのファイルを開きます。 → 外部プレーヤー
TLタイムライン（Timeline） — スクリプトのグラフを表示・非表示します。
HMヒートマップ（Heatmap） — ファイル全体の強弱を色の帯で示します。
AV音声・字幕トラック — 内蔵の音声トラックと字幕トラックを選びます。 → 音声と字幕
評価 — 再生画面のままスコアを付けられます。ライブラリの並べ替えや絞り込みに使われます。
FITフィット — 映像全体が見えるように合わせます。黒い余白が出ることがあります。
FILLフィル — 余白なく画面を埋めます。映像の端が切れることがあります。
全画面 — F キーと同じです。

タイトルバー#

ウィンドウ最上部にアプリ名とバージョンが表示され、右に Stop all devices ボタンがあります。接続中のすべてのデバイスを一度に止める緊急停止ボタンです。 → 安全と緊急停止

ライブラリ

ファイルが増えるとフォルダーを1つずつ開くのが面倒になります。ライブラリはよく使うフォルダーを登録して、サムネイルカードでまとめて見渡せるようにします。

複数のフォルダーを登録する#

v0.6.0 から名前を付けたライブラリフォルダーを複数登録できます。設定 → 一般の Library folders で管理します。各フォルダーは独立して扱われるため、1つを無効にしても残りはそのままです。

  • Add folder — フォルダーを追加します。選択ダイアログで複数まとめて選べます。
  • 名前 — パスの代わりに Local Library、NAS Library のようにわかりやすい名前を付けます。
  • トグル — 一時的に外したいときにオフにします。無効にしたフォルダーは設定がそのまま保存され、スキャン対象からのみ外れます。
  • ごみ箱 — 登録を解除するだけで、実際のファイルは削除しません。
スクリプトフォルダーもここで

ダウンロードしたスクリプトをまとめる Script Storage Folder も同じ画面で指定します。ここを設定しておくと、スクリプトの自動照合とプラグインのダウンロードがどちらもこのフォルダーを使います。 → スクリプトを扱う

NAS を使う場合

ローカルと NAS の一覧はキャッシュ上で統合され、重複なく1つに見えます。起動時はまずキャッシュの内容を表示し、そのあとフォルダーを1つずつ順番に更新します。複数のフォルダーを同時に読まないため、起動時にディスクやネットワークへ負荷が集中しにくくなります。

絞り込みと並べ替え#

フィルターは保存され、次に開いたときも維持されます。

機能説明
検索タイトルとパスで探します。
メディア種別映像のみ / 音声のみに分けて表示します。

再生時間で並べ替えるには長さが必要ですが、これはバックグラウンドで自動的にスキャンされます。ファイルが多いと最初は一部だけ表示され、徐々に埋まっていきます。

カードを扱う#

  • カードサイズ — スライダーで一画面に表示する数を調整します。
  • サムネイルメニュー — カードから代表画像を変更したり作り直したりできます。
  • 評価 — カードでスコアを付け、再生中も再生バーの ☆ から変更できます。

リピート・自動で次を再生・シャッフル#

似ているようで別物の3つです。最初は混同しやすいので分けて説明します。

リピート 🔁

いま再生中のこのファイルだけを繰り返します。

Auto Next Play

ファイルが終わると次のファイルへ自動で進みます。設定でオンにします。

シャッフル 🔀

一覧をランダムな順で再生します。

AB区間リピート#

映像の特定の区間だけを繰り返し見たいときに使います。開始点（A）と終了点（B）を指定すると、その間だけが繰り返されます。

  1. 繰り返したい区間の開始位置で A 地点を指定します。
  2. 区間の終了位置で B 地点を指定します。
  3. 区間リピートが始まります。エディターを開けば地点を正確な値に整えられます。

A・B の指定とエディターを開く操作は、すべてショートカットに割り当てられます。（キーボードショートカット）

画面フィット — FIT と FILL#

映像の比率とウィンドウの比率が違うとき、どちらを優先するかを選ぶボタンです。

  • FIT — 映像全体が見えるように合わせます。上下または左右に黒い余白が出ることがあります。
  • FILL — 画面をすべて埋めます。映像の端が切れることがあります。

全画面#

F で全画面になります。全画面でもサイドバーを呼び出せるので、ファイルを変えるために抜ける必要がありません。

v0.6.0 から全画面コントロールの表示方法を設定で変更できます。

  • 下端からのみ表示する — 画面のどこでマウスを動かしてもコントロールが出ないようにします。
  • 背景の不透明度 — コントロール背後の背景を濃くしたり薄くしたりします。
  • 縦位置 — コントロールが出る高さを調整します。

常に手前に表示する#

ほかのウィンドウを使いながら再生画面を見続けたいとき、ウィンドウを常に最前面に固定できます。

やり直しと復旧#

設定をいろいろ触って分からなくなったら、設定 → 復旧で初期状態に戻せます。全体リセットではキャッシュした再生時間、ストローク範囲、プレーヤー・ライブラリ・ワークスペース・最近のメディア・サイドバーの状態もまとめて片付けられます。

スクリプトを扱う

スクリプトが自動で認識されない、認識されたがタイミングが合わない、動きが強すぎる——そんなときにどこを触るかをまとめました。このページだけでスクリプト関連の問題はほとんど解決します。

スクリプトはどう見つかるのか#

ScriptPlayer+ は次の順で一致するスクリプトを探します。

  1. 同じフォルダーの同じ名前

    もっとも確実な方法です。映像.mp4 の隣に 映像.funscript を置けばすぐ認識されます。

  2. 指定したスクリプトフォルダー

    スクリプトを別にまとめているなら、設定 → 一般 → Script Storage Folder でそのフォルダーを指定します。（サイドバーの Folder 横の小さなボタンでも指定できます。）以降はそのフォルダーも一緒にスキャンします。

  3. ライブラリが収集したスクリプト

    登録済みのライブラリフォルダーがインデックスしたスクリプトも候補に入ります。

  4. 候補が1つだけなら自動選択

    名前が完全に一致しなくても、明確に1つに絞られれば自動的に選ばれます。

スクリプトバリアントパネル#

同じ映像に合うスクリプトが複数あることがあります。Soft のように括弧でラベルが付いたバリアントが代表例です。そんなときはサイドバーの Script Variants パネルから、再生を止めずにすぐ差し替えられます。

再生時間で探す#

名前がまったく違うのに内容は合っているスクリプトを探したいことがあります。v0.6.0 で入った再生時間ベースの検索は、スクリプトのタイムライン長が映像の長さにどれだけ近いかで候補を順位付けします。

  • 映像があるフォルダー、指定したスクリプトフォルダー、ライブラリがインデックスしたスクリプトをすべて候補にします。
  • 長さが近い順に並ぶので、上の候補から試せばよいです。

タイミングが合わないとき — スクリプトオフセット#

正の値（+）は動きを早め、負の値（-）は遅らせます。動きが映像より約0.2秒遅い場合は現在の値に0.2秒を加え、約0.2秒早い場合は0.2秒を引いてください。入力欄の単位は秒です（0.2秒 = 200ms）。

映像より動きが少し早い、または遅いときに使います。再生バーの +0ms ボタンから調整します。

  • 範囲は -60秒から+60秒までです。
  • 小数秒単位で直接入力でき、微調整ボタンで少しずつ動かすこともできます。
  • オフセットは可能ならスクリプトごと、それ以外はメディアごとに保存されます。同じスクリプトを使うと保存済みの補正値が適用される場合があります。
  • 増やす・減らす・リセットはすべてショートカットに割り当てられます。
合わせるコツ

目立つ動きがある地点へ移動しておき、再生しながらオフセットを少しずつ動かしてみてください。タイムラインのグラフの山と画面の動きが重なる地点が正解です。

動きが強すぎるとき — ストローク範囲#

再生バーの STR でデバイスが実際に動く範囲を調整します。スクリプトを編集せずに強さを下げたり上げたりできます。

同じ設定を設定 → デバイスでさらに細かく扱えます。

項目役割
Stroke Range Min / Max動きの下限と上限を 0%～100% の間で決めます。
Range Extender最終的なストローク範囲を適用する前に、50% の中心を基準に L0 の動きを大きくしたり小さくしたりします。
Inverse Strokeデバイスへ送る前に、スクリプトの位置の値を上下反転します。
Amplitude setting behavior v0.6.0この値をスクリプトごとに個別に記憶するか、すべてのメディアで1つを共有するかを選びます。
中心を保つ範囲 v0.6.0回転軸のように中心が基準の軸は、中心を保ったまま幅だけを縮めます。
はじめて使うとき

範囲を狭くして始め、慣れてきたら少しずつ広げてください。速度制限も併用するとより安全です。 → 安全と緊急停止

空白区間の扱い#

スクリプトに動きのない長い区間があるときに使うオプションです。

  • ギャップ補完（Fill gaps） — 空白区間を生成した動きで埋めます。
  • 自動スキップ — 空白区間を飛ばします。すぐ飛ばさず少し待ってから飛ばすように遅延を設定できます。
  • 疎なスクリプトの補正 — 点がまばらなスクリプトをなめらかに整えます。

スクリプトがまったくないとき — ランダムストローク#

スクリプトがない映像でも動きを生成できます。プリセットは基本の焦らしパターンと、より強いパターンが分かれています。

生成された動きはなめらかさ（スムージング）を Off・Light・Balanced・Strong から選べます。方向が急に折り返さず加減速のカーブを描くため、ずっと自然です。

映像からスクリプトを作る# 実験的機能

v0.4.0 から、映像の動きを解析してファンスクリプトを作り、メディアの隣に保存できます。解析には外部の FFmpeg 実行ファイルが必要です。 → FFmpeg互換再生

参考

モーション解析は実験的機能です。結果の品質は映像によって大きく変わり、生成されたスクリプトは手で整える必要がある場合があります。

多軸スクリプト#

複数の軸を同時に使うスクリプトは、次の3つの形式に対応しています。

  • 1つのファイル内に axes[] で軸を収めた形式
  • 1つのファイル内に channels{} で軸を収めた形式
  • 軸ごとにファイルが分かれた形式（例: 映像.L0.funscript、映像.R0.funscript）

v0.6.0 からは軸ごとにスクリプトの出どころを差し替えられます。たとえば多軸バンドルをそのまま使いながら、L0 軸だけ別ファイルに置き換えられます。ある軸の動きを別の軸から引く軸ソース連携にも対応します。（例: L0 → R0）

多軸スクリプトを画面で見る方法はタイムラインとヒートマップにあります。

スクリプトを点検する#

スクリプトの動きがおかしいとき、どんな値が入ってきているかを確認できる画面があります。

タイムラインとヒートマップ

スクリプトを目で確かめる2つの方法です。タイムラインはいまこの瞬間を、ヒートマップはファイル全体を示します。

タイムライン TL#

再生位置に沿って流れるリアルタイムのグラフです。再生バーの TL ボタンで表示・非表示します。

軸を選ぶ

多軸スクリプトを開くと、タイムラインの上に AXES の行が現れます。

  • All — すべての軸を一度に重ねて表示します。
  • 軸ボタン（L0、L1、R0、R1 …） — 押して個別に表示・非表示します。ボタン横の数字はいまのその軸の値です。
  • ダブルクリック — その軸だけを残してほかを隠します。1つの軸をじっくり見るときに便利です。

高さの調整

映像とタイムラインの境界を上下にドラッグするとタイムラインの高さが変わります。軸が多いときは広げておくとぐっと見やすくなります。

ヒートマップ HM#

ファイル全体を1本の横帯に圧縮して示します。色は速度を表します — 緑が遅く、黄を経て赤へ進むほど速くなります。

どこが激しい区間かを再生前に把握できるので、見たい位置へ直接飛ぶときに便利です。

参考

ライブラリの一覧やカードにはヒートマップは表示されません。ヒートマップは再生画面でのみ見られます。

タイムラインの設定#

  • 表示コントラスト — グラフを濃くまたは薄く
  • 速度による色分けのオン / オフ
  • 既定の高さ

音声と字幕

音声ファイルの再生、音量ブースト、字幕の読み込みと内蔵トラックの選択まで、音と字幕に関する内容です。

音声ファイルの再生#

MP3・FLAC のような音声も、映像とまったく同じようにスクリプトを付けて再生できます。映像がないので代わりにカバー画像を表示します。

カバー画像は次の順で探します。

  • 音声ファイル内のメタデータ画像
  • 同じ作品フォルダー内の画像ファイル

音量ブースト 150%# 実験的機能

録音が小さくて聞き取りにくい音源のために、最大150%まで音量を上げられます。ピークリミッターが同時に働き、急に大きく跳ねるのを防ぎます。

注意

イヤホンを使っているなら、ブーストをオンにする前に音量を下げてください。

字幕#

外部字幕ファイル

.srt、.vtt、.txt に対応します。映像と同じ名前なら自動で見つけて読み込みます。自動で認識されない場合は手動で読み込むこともできます。

内蔵字幕

映像ファイル内のテキスト字幕トラックも使えます。再生バーの AV ボタンから選びます。ただし外部の FFmpeg がインストールされている必要があります。

字幕の種類対応
SRT, ASS/SSA, WebVTT, mov_text対応 — テキストベースのトラックです。
PGS、DVD 字幕一覧には出ますが表示できません。画像ベースの字幕のため描画しません。

音声トラックを選ぶ#

The Handy

The Handy はインターネットを経由して動作します。スクリプトをサーバーへアップロードし再生時刻を合わせる方式のため、接続品質が体感に直接影響します。

接続する#

  1. 接続キーを確認する

    The Handy 本体の画面またはアプリで接続キー（Connection Key）を確認します。

  2. 設定 → デバイスに入力する

    ScriptPlayer+ の設定 → デバイスで The Handy を選び、接続キーを入力します。

  3. 接続を確認する

    接続されると状態表示が変わります。映像を再生すると、スクリプトが自動でアップロードされ同期します。

同期と時間オフセット#

The Handy は API v2 で動作します。再生を始めるとスクリプトをアップロードし、サーバーの時計に合わせて再生位置を同期します。

アップロードが終わったら自動で再生する

設定 → 再生の Auto Play After Handy Sync をオンにすると、アップロードと HSSP 同期が終わった瞬間に再生が始まります。毎回同期の完了を待って再生ボタンを押す必要がなくなります。

全体的に動きが少し早い、または遅いときは時間オフセットで補正します。特定の映像だけずれる場合はスクリプト側の問題である可能性が高いので、代わりにスクリプトオフセットを使ってください。

ネットワーク診断#

設定 → Handy ネットワーク診断で接続品質を実際に測定できます。動きがよく途切れたり遅れたりするなら、ここから確認してください。

P95 レイテンシ遅い側5%のレイテンシです。この値が大きいと、ときどき大きく跳ねるという意味です。
ジッターレイテンシのばらつきです。大きいほど同期が不安定になります。

互換モード#

旧型のハードウェアや反応の遅い機器のための互換モードがあります。既定の設定で動作が不安定なら、このモードを試してください。

Intiface / Buttplug

Intiface は複数メーカーのデバイスを1つの規格でまとめる中継ソフトウェアです。v0.6.0 から ScriptPlayer+ 内に専用のワークスペースができ、別の窓を行き来せずに扱えます。

2つの接続方式#

内蔵エンジン

ScriptPlayer+ に入っている軽量エンジンを使います。別途インストールするものがなくもっとも手軽です。

外部の Intiface Central

すでに使っている Intiface Central へ接続します。より多くのデバイスと設定を扱えます。

接続する#

左レールの Intiface アイコンを押すと Intiface Device Manager が開きます。画面上部に 1 Connect → 2 Find device → 3 Configure → 4 Playback の4ステップが表示され、いまどの段階かと次に何をするかを併せて示します。

  1. Connect — 接続方式を選ぶ

    Built-in engine と External Central のどちらかを選びます。内蔵エンジンならアドレス（ws://127.0.0.1:…）が表示され、外部を選ぶ場合は接続先アドレスを入力します。

  2. Find device — デバイス検索

    スキャンを始めると Bluetooth・HID・設定済みのシリアルデバイスを探します。デバイスの電源を入れ、ペアリング待ちの状態でお待ちください。複数のデバイスを同時に選べます。

  3. Configure — 出力マッピング

    Output mapping でデバイスを選び、使える機能をそれぞれどのスクリプト軸に割り当てるか指定します。

  4. Playback — 再生

    映像を再生すると、割り当てた軸へ出力されます。バッテリー残量もこの画面で確認できます。

接続状態はレールのアイコンにも未接続・処理中・接続済み・エラーとして表示されます。

機能マッピング#

Buttplug デバイスの機能は3種類に分かれます。それぞれ好きな軸に割り当てられます。

  • リニア（Linear） — 前後に動く動作。通常は L0 軸を割り当てます。
  • ローテート（Rotate） — 回転する動作。通常は R0 軸を割り当てます。
  • スカラー（Scalar） — 振動の強さのように、大きさ1つで表される動作です。

スクリプトにない軸が必要なら、軸ソース連携で別の軸から値を引けます。たとえば L0 の動きを R0 の出力として使う、といった具合です。

ほかのアプリと併用する#

内蔵エンジンは一度に1つだけ

内蔵の Intiface エンジンは Buttplug クライアントを1つだけ受け付けます。ScriptPlayer+ とほかのアプリが同時に制御することはできません。

そのためにハンドオフ機能があります。Intiface Device Manager の Allow FapTap / external app ボタンを押すと、エンジンは動いたままで ScriptPlayer+ だけが接続を手放します。その間に FapTap のような別のクライアントが同じアドレスへ接続でき、そのアプリが切断すると ScriptPlayer+ が再接続します。

順番が大切です

ほかのアプリを先に立ち上げてから ScriptPlayer+ を接続しようとすると失敗します。まず ScriptPlayer+ 側で接続を手放してから、ほかのアプリを接続してください。

デバイスごとのウォッチドッグ#

デバイスを複数使うとき、1つが遅くなったり失敗を繰り返したりすると、ほかのデバイスまで引きずられて止まることがありました。v0.6.0 からはデバイスごとに独立したウォッチドッグが付き、問題のある1台のせいで残りの出力が止まることはありません。

Windows 内蔵エンジンの範囲#

Windows 用の内蔵エンジンが扱える接続は次のとおりです。

  • Bluetooth LE
  • HID
  • 明示的に指定した Bluetooth RFCOMM COM ポート1つ — TCode v0.3、115200 baud としてマッピングされます。
このシリアル経路の制限

この経路は FunOSR SR1 が使う単一のリニア軸定義だけを公開します。USB シリアルアダプターや SR6 の完全な多軸シリアルマッピングが必要な場合は、FunOSR プロバイダーを直接使うか、外部の Intiface Central を使ってください。

FunOSR

FunOSR はシリアル（COM）ポートへ直接信号を送る方式です。中継ソフトウェアを通らないため遅延が少なく、多軸マッピングを細かく扱えます。

ポートを選ぶ#

設定 → デバイスで FunOSR を選び、COM ポートを指定します。v0.6.0 からポート認識が改善され、次の順で適切なポートを先に提案します。

  1. FunOSR として明確に識別されるポート
  2. CH340 / CH341 アダプター
  3. USB 識別子 1A86:7523
ポートが一時的に見えなくても

起動時に検索結果が空でも、保存した COM パスは維持されます。デバイスを後から挿しても設定が失われません。

出力の調整#

設定 → デバイスで次を調整します。

項目説明
更新レート1秒あたり何回コマンドを送るかを決めます。上げすぎるとかえって不安定になることがあります。
軸マッピングスクリプトの軸をデバイスの実際の軸へ結び付けます。
モーションスムージング動きをなめらかに整えます。
Custom speed limit軸ごとの最高速度を spm（1分あたりのフルストローク回数）単位で制限します。全体の制限に従うか軸ごとに設定するかも選べます。

軸テストと中央合わせ#

軸が正しくつながっているか確かめるために映像を再生する必要はありません。設定 → デバイス最下部の Device Test Panel で L0・V0・V1・R0 のボタンを押すと、その軸へ短いコマンドを直接送れます。Stop で即座に止まり、中央位置コマンドで真ん中へ戻します。

軸が入れ替わっていないか確かめるとき

L0 を押したのに回転が動くなら、軸マッピングが間違っています。このパネルで1つずつ押せば、どの軸がどこにつながっているかすぐわかります。

スクリプトが実際にどのファイルからどう読み込まれたかを確認するには、Show Script Debug Info をオンにしてください。再生画面にスクリプトのパス・出どころ・軸の一覧・保存されたオフセットが表示されます。

SR1 関連のオプション#

  • Bluetooth COM 出力 — 25Hz の上限と TCode 補間を適用してよりなめらかに出力します。待機中は保持信号を送りません。
  • SR1 2.0 Twist 静音モード — R0 の回転速度の上限を調整して騒音を抑えます。

一時停止と再開#

シリアル送信が遅れたあとに再生を再開すると、遅れた分を一気に取り戻そうとしてデバイスが大きく跳ねることがあります。v0.5.1 と v0.6.0 でこの部分が強化されました。

  • 再開への移行は、設定した安全開始時間が過ぎれば確実に完了します。
  • 遅れた進行量は上限を設けて取り戻すため、大きな飛びは起きません。
  • 安全移行の状態に留まってスクリプトへ戻れなくなる問題が解決されました。

モバイル・コントローラーリモート

専用の Bluetooth リモコンやスマートフォンで再生を操作できます。キーボードに手を伸ばさずに再生・停止・次のファイルへ進めたいときに使います。

接続前の準備#

Androidスマートフォン：設定のGet Android appからアプリをインストールし、スマートフォンでリモート画面を開きます。Bluetoothをオンにし、アプリが求める付近のデバイスの権限を許可してください。リモート画面のBLEスイッチをオンにして接続待機状態にし、表示されたデバイス名を確認します。

専用リモコン：対応ファームウェアをインストールしたデバイスの電源を入れます。インストールが必要な場合は、設定のOpen flasherで該当デバイスの案内に従ってください。PCのBluetoothもオンにしてから、以下のペアリングを行います。

ペアリングする#

  1. 設定を開く

    設定 → モバイル/コントローラーリモートへ進みます。

  2. 接続

    PCでConnectを押し、デバイス選択画面でスマートフォンに表示された名前、または専用リモコンを選びます。

  3. 6桁のコードを入力

    リモートの画面に出た6桁のペアリングコードを入力し、Pair を押します。

安全と緊急停止

デバイスを使う以上、いつでもすぐ止められる必要があります。このページはその方法と、あらかじめ設定できる制限を扱います。デバイスを初めて使うなら、まずこのページを読んでください。

グローバル緊急停止（E-Stop）# v0.6.0

ウィンドウ右上の Stop all devices ボタンです。いまどのプロバイダーを使っているかに関係なく、接続中のすべてのデバイスへ停止要求を送ります。

  • 再生を止め、Handy・Intiface・FunOSR のすべてへ停止コマンドを送ります。
  • 停止要求には制限時間があり、無限に待つことはありません。
  • 失敗またはタイムアウトしたデバイスは一覧に残り、再試行できます。

このボタンはデバイスが接続されているときにタイトルバーと全画面に現れます。表示するかどうかは設定 → デバイスの Show E-Stop button でオフにできます。

ボタンを隠す前に

隠していてもIntiface 管理画面の停止コントロールはそのまま残ります。ただしそちらは画面を一度移動しないと届きません。隠す前にその場所を必ず確認しておいてください。

一度に1つのプロバイダー#

現在の制限

デバイス出力は一度に1つのプロバイダーのみ使用します。Handy と Intiface / FunOSR を同時に出力することはまだできません。

プロバイダーを切り替えるときは、前の接続が片付いたあとに新しい接続がつながります。v0.6.0 で、FunOSR から Handy や Intiface へ移るときに片付け処理で切り替えが止まる問題が解決されました。

おすすめの習慣#

  • 新しいスクリプトを初めて再生するときは、範囲を狭くしてどんな動きかを先に確かめます。
  • ヒートマップで赤い区間がどこかを先に確認します。 → タイムラインとヒートマップ
  • E-Stop ボタンの位置を手に覚えさせておきます。
  • デバイスを動かしたまま席を離れないでください。

FFmpeg互換再生

用意する方法#

ScriptPlayer+ は次の順で FFmpeg を探します。いずれか1つを満たせば十分です。

  1. 設定から自動インストール もっとも簡単

    設定画面のボタンから、OS のパッケージマネージャー経由でインストールできます。Windows は winget、macOS は Homebrew、Linux は対応するパッケージマネージャーを使います。ユーザーが自分で押したときだけ実行されます。

  2. 環境変数 FFMPEG_PATH

    実行ファイルのパスをこの環境変数に指定しておけば、それを使います。

  3. 一般的なインストール先またはシステムの PATH

    すでに FFmpeg がインストールされていれば、たいてい自動で見つかります。

  4. 自分で選ぶ

    設定で FFmpeg の実行ファイルを直接指定します。自動検索が失敗したときの確実な方法です。

互換モードを選ぶ#

設定 → 再生の Video Compatibility Mode で、どこまで介入するかを決めます。症状に応じて選んでください。

症状選ぶもの
問題なく再生できるAuto — 必要なときだけ自動で介入します。既定値です。
映像は出るが音が出ない音声互換モード — 音だけを FFmpeg で処理します。
画面が黒い、またはまったく開かない完全互換モード — 映像まで FFmpeg で処理します。
変更後は開き直しが必要です

互換モードを変えたら、映像を閉じて開き直すと適用されます。

パッケージに含まれない理由

ScriptPlayer+ のリリースパッケージには FFmpeg の実行ファイルも FFmpeg のソースも入っていません。互換再生・サムネイルの代替生成・モーション解析はすべて外部の実行ファイルのみを使います。

プラグイン

スクリプトの提供元を自分で追加する機能です。既定で含まれる、あるいは推奨される提供元はひとつもありません。必要なときに自分でインストールして使います。

.funplugin とは#

.funplugin ファイルはJSON マニフェストにすぎません。どこでスクリプトを探すかという情報だけが入っており、実行コードは含まれていません。

コードは実行しません

ScriptPlayer+ はプラグインのコードをアプリ内で実行しません。データ専用のマニフェストだけを読むため、プラグインがアプリを勝手に操作することはできません。

インストールと管理#

左レールのプラグインアイコンで管理します。インストール時に次が検証されます。

  • マニフェスト検査 — 形式が正しいか厳密に確認します。
  • 権限の確認 — 何を要求しているか表示します。
  • 署名 — 発行元の署名があれば検証します。（任意）
  • 信頼情報の表示 — 上の結果をユーザーが見えるように示します。

ダウンロードしたスクリプト#

プラグインで取得したスクリプトは、指定したスクリプトフォルダーに保存されます。指定していなければアプリが管理するフォルダーに保存されます。ダウンロードが終わると、いま再生中のメディアへすぐ適用されます。

複数を同時に取得するときは、それぞれの進行状況が個別に表示されます。

トラブルシューティング

よくある症状と確認の順番をまとめました。上から順に試してみてください。

インストール・起動#

Windows で「PC が保護されました」と警告が出ます

Windows パッケージに Authenticode 署名がないため SmartScreen が出す案内です。詳細情報 → 実行を押せばインストールできます。

macOS でアプリが開きません

システム設定 → プライバシーとセキュリティで「このまま開く」を押してください。macOS Monterey 12 以降が必要な点も確認してください。

Linux で起動しません

Ubuntu / Kubuntu 24.04 以降なら DEB パッケージをインストールしてください。AppImage とアーカイブ版はシステムのユーザー名前空間の制限を回避できず、ScriptPlayer+ は --no-sandbox で自動起動することもありません。

再生#

映像が開かない、または音だけ出ます

  1. 拡張子が対応一覧にあるか確認します。 → 対応ファイル形式
  2. コンテナは合っていてもコーデックが違うことがあります。FFmpeg を用意して互換再生をオンにしてみてください。
  3. それでもだめなら外部プレーヤーで開いてみます。

VR映像が2つに割れて見えます

左右分割（SBS）の映像が平面で再生されている状態です。投影方式を VR180 正距円筒に、元の配置を左右分割に指定してください。 → VR・360度映像

サムネイルが作られません

Chromium がその映像をデコードできない場合です。FFmpeg があれば代替の方法でサムネイルを作ります。

スクリプト#

スクリプトが自動で認識されません

  1. スクリプトが映像と同じフォルダーに同じ名前であるか確認します。
  2. 別にまとめているなら、サイドバーでスクリプトフォルダーを指定します。
  3. サイドバーで再スキャンを押してみます。
  4. 名前がまったく違うなら再生時間で探すを使います。

動きが映像より早い、または遅いです

再生バーの+0msでスクリプトオフセットを調整します。動きが遅ければ値を増やし、早ければ減らします。可能ならスクリプトごと、それ以外はメディアごとに保存されます。すべて同じようにずれる場合はデバイス側の時間オフセットも確認してください。→ The Handy

認識はされたが別のスクリプトを使いたいです

サイドバーの Script Variants パネルで差し替えられます。 → スクリプトを扱う

デバイス#

デバイスがまったく動きません

  1. スクリプトが実際に読み込まれたか確認します。タイムラインのグラフは見えていますか？
  2. デバイスの接続状態が接続済みか確認します。
  3. ストローク範囲が0 に近いほど狭められていないか確認します。 → スクリプトを扱う
  4. 緊急停止を押したままの状態でないか確認します。 → 安全と緊急停止
  5. FunOSR ならライブ軸テストでデバイス自体が反応するか見ます。

動きが途切れる、または遅れます

  • The Handy — ネットワーク診断を実行してレイテンシとジッターを確認します。値が悪ければ有線接続や別のネットワークを試してください。
  • FunOSR — 更新レートを下げてみます。高すぎるとかえって不安定になります。
  • Intiface — デバイスを複数使っているなら、1台だけにして試します。

別のデバイスに切り替えられません

出力は一度に1つのプロバイダーのみ使用します。前の接続の片付けに少し時間がかかることがあるので、数秒待ってから再度お試しください。 → 安全と緊急停止

ほかのアプリが Intiface デバイスを認識できません

内蔵の Intiface エンジンはクライアントを1つだけ受け付けます。Intiface 管理画面のハンドオフコントロールで制御権を渡してください。 → Intiface / Buttplug

それでも解決しないとき#

  1. 設定 → 復旧でリセットを試します。 → 再生
  2. 最新バージョンか確認します。 → インストール
  3. GitHub Issuesへお問い合わせください。デバイスの問題なら診断情報をコピーして一緒に載せると、ぐっと早く進みます。
