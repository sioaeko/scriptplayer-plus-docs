ScriptPlayer+ Documentation

ScriptPlayer+ is a desktop player that plays local video and audio alongside funscripts and controls The Handy, Intiface and FunOSR devices in sync with the script. This guide covers installation, everyday use, device connections and troubleshooting.

Quick start How to install

Windows · macOS · Linux · These docs describe the v0.6 series.

Install

ScriptPlayer+ is installed from the Windows, macOS and Linux packages on GitHub Releases. Your operating system may show a security warning the first time you run it; how to get past each one is below.

Download#

Every build is published on the latest GitHub release page. Pick the file for your operating system.

PlatformPackageNotes
Windows x64 Installer (.exe) or portable .zip To run without installing, take the portable ZIP and just unpack it.
macOS x64 / arm64 .dmg or .zip Apple Silicon and Intel have separate files. Take the one that matches your Mac.
Linux x64 .deb · AppImage · archive package On Ubuntu / Kubuntu 24.04 and newer, use the DEB.

Windows#

  1. Run the installer

    Running the downloaded .exe shows the licence agreement (EULA) first. Read it, accept, and the install continues.

  2. If SmartScreen warns you

    The Windows packages are not Authenticode signed, so Microsoft Defender SmartScreen may show “Windows protected your PC”. Click More info → Run anyway to continue.

  3. If you use the portable ZIP

    Run the executable inside the unpacked folder. Settings and caches are stored in your user folder.

macOS#

Minimum version

The Electron runtime upgrade in v0.6.0 raised the minimum macOS version from Big Sur 11 to Monterey 12. v0.6 and later will not run on Big Sur.

  1. Open the DMG and move the app

    Open the .dmg and drag the ScriptPlayer+ icon into your Applications folder.

  2. If it says the app cannot be opened

    Gatekeeper may report that it cannot verify the developer. Go to System Settings → Privacy & Security and press the “Open Anyway” button that appears near the bottom.

Linux#

On Ubuntu / Kubuntu 24.04 and newer, use the DEB package. Those releases restrict unprivileged user namespaces, and the Chromium sandbox needs an executable-scoped AppArmor profile to work — a profile that ships only in the DEB.

  • DEB — installs the AppArmor profile with it. The safest choice on 24.04 and newer.
  • AppImage — moved to a static runtime in v0.6.0, so libfuse.so.2 is no longer required.
  • Archive package — for distributions where unprivileged user namespaces are available.
The sandbox is never disabled

ScriptPlayer+ refuses to fall back to --no-sandbox when it meets a system-wide namespace restriction. If the portable AppImage or the archive package will not start, install the DEB instead.

Updates#

When a new version ships, the app tells you. You can download and install straight from the notice, and a hotfix released under the same version number is detected too. How it checks is set in Settings → General.

Quick start

Once it is installed, start here. Five steps and you have video playing, a script attached and a device moving.

The five steps#

  1. Open the folder your media is in

    Click Folder at the top left and pick the folder holding your videos. For a single file, you can just drag and drop it onto the window.

  2. Pick a video from the list

    Click a file in the sidebar list and playback starts immediately. A green document icon to the right of the name means a matching funscript was found.

  3. Check the script actually loaded

    If you can see the heatmap band and the timeline graph under the video, the script was read correctly. If not, switch them on with the HM and TL buttons on the playback bar.

  4. Connect your device

    Click the Device icon on the left rail, choose your device and connect. For per-device setup, see The Handy, Intiface and FunOSR.

  5. Play, then tune the intensity

    Press Space to play. If the motion is too strong or too weak, narrow or widen the stroke range under STR. If the timing is off, adjust the offset from the +0ms button.

Worth knowing first
  • A script is normally picked up automatically if it sits in the same folder under the same name as the video (video.mp4 ↔ video.funscript).
  • If you keep scripts in their own folder, set it as the script folder in Settings.
  • The first time you use a device, it is safer to start with a narrow stroke range.

Using the library instead of opening folders#

Rather than opening a folder every time, register the folders you use often in the library and browse them as thumbnail cards. Start from the Library icon at the bottom of the left rail. See Library for the details.

Library

Once you have a lot of files, opening one folder at a time gets tedious. The library lets you register the folders you use often and skim them all as thumbnail cards.

Registering several folders#

Since v0.6.0 you can register several named library folders. They are managed under Library folders in Settings → General. Each one is handled independently, so switching one off leaves the rest untouched.

  • Add folder — adds a folder. The picker accepts several at once.
  • Name — give it something readable like Local Library or NAS Library instead of a path.
  • Toggle — switch a folder off to leave it out for a while. A disabled folder keeps its settings and is only excluded from scans.
  • Bin — removes the registration only. Your actual files are untouched.
The script folder is here too

The Script Storage Folder that collects downloaded scripts is set on the same screen. Once it is set, both automatic script matching and plugin downloads use it. → Working with scripts

If you use a NAS

Local and NAS catalogues are merged from cache into one deduplicated list. On startup the cached contents appear first, then each folder is refreshed one after another. Because folders are not read in parallel, the disk and network are not hammered all at once at launch.

Filtering and sorting#

Filters are remembered and still applied next time you open the library.

ControlWhat it does
SearchSearches title and path.
Media typeSplits the view into video only or audio only.
Script categoryFilters single-axis and multi-axis scripts separately.
RatingShows only items you have scored.
SortSorts by path, file name, rating, duration or last-modified time.

Sorting by duration needs the lengths first, and those are scanned automatically in the background. With a lot of files you will see part of the list at first, filling in as it goes.

Working with cards#

  • Card size — the slider changes how many fit on screen.
  • Thumbnail menu — change or regenerate the cover image straight from the card.
  • Rating — score from the card, or change it mid-playback with ☆ on the playback bar.

Hover preview#

Rest the pointer on an entry in the file list and a short video preview plays without opening the file. You no longer have to open things one by one just to see what they are.

Repeat, Auto Next Play and shuffle#

Three things that look alike but are not. They are easy to confuse at first, so here they are side by side.

Repeat 🔁

Loops only the file playing now.

Auto Next Play

When a file ends, moves on to the next one. Switched on in Settings.

Shuffle 🔀

Plays the list in random order.

AB segment repeat#

For replaying one stretch of a video over and over. Mark the start (A) and the end (B), and only that stretch loops.

  1. At the start of the stretch you want, set point A.
  2. At the end of it, set point B.
  3. The loop begins. Open the editor to fine-tune both points to exact values.

Setting A, setting B and opening the editor can all be bound to keys. (Keyboard shortcuts)

Fitting the frame — FIT and FILL#

When the video's aspect ratio differs from the window's, these decide which one wins.

  • FIT — scales so the whole video is visible. Black bars may appear above and below, or at the sides.
  • FILL — fills the frame completely. The edges of the video may be cropped.

Fullscreen#

F enters fullscreen. The sidebar can still be summoned there, so you do not have to leave just to change file.

Since v0.6.0 you can change how the fullscreen controls appear.

  • Reveal from the bottom edge only — so moving the pointer anywhere on screen does not raise the controls.
  • Background opacity — makes the ground behind the controls heavier or lighter.
  • Vertical position — sets how high the controls sit.

Keeping the window on top#

To keep watching while you work in another window, pin the window in front of everything else.

Resetting and recovery#

If you have changed enough settings to tangle things up, Settings → Recovery puts them back. A full reset also clears cached durations, stroke ranges, and the player, library, workspace, recent-media and sidebar state.

Working with scripts

What to reach for when a script is not detected, or is detected but out of sync, or drives the device too hard. This one page covers most script problems.

How a script gets found#

ScriptPlayer+ looks for a matching script in this order.

  1. Same name, same folder

    The most reliable arrangement. Put video.funscript beside video.mp4 and it is picked up at once.

  2. The configured script folder

    If you keep scripts apart, point Settings → General → Script Storage Folder at that folder. (The small button beside Folder in the sidebar sets it too.) It is then scanned as well.

  3. Scripts indexed by the library

    Scripts already indexed by your registered library folders are candidates too.

  4. A single candidate is chosen automatically

    Even when the names do not match exactly, a candidate that narrows down to exactly one is selected for you.

The Script Variants panel#

Sometimes several scripts match the same video — a labelled alternate like Soft in brackets is the usual case. The Script Variants panel in the sidebar swaps between them without stopping playback.

Matching by duration#

Sometimes the right script has an entirely different name. The duration-based search added in v0.6.0 ranks candidates by how closely the script's timeline length matches the video's.

  • It considers the media folder, the configured script folder and everything the library has indexed.
  • Results are ordered by how close the lengths are, so work down from the top.

When the timing is off — script offset#

Positive (+) values advance movement; negative (-) values delay it. If movement is about 0.2 seconds late, add 0.2 seconds to the current value. If it is about 0.2 seconds early, subtract 0.2 seconds. The input uses seconds: 0.2 seconds = 200ms.

Use this when the motion runs slightly ahead of or behind the video. Adjust it from the +0ms button on the playback bar.

  • The range is -60s to +60s.
  • You can type a value in decimal seconds, or nudge it with the fine-step buttons.
  • The offset is saved per script when possible, otherwise per media file. Reusing the same script may apply its saved offset.
  • Increase, decrease and reset can all be bound to keys.
How to land it

Seek to a moment with an obvious movement, then nudge the offset while it plays. You have it when the peaks in the timeline line up with what you see on screen.

When the motion is too strong — stroke range#

STR on the playback bar sets how far the device actually travels. You can turn the intensity down or up without editing the script.

The same settings are available in more detail under Settings → Device.

SettingWhat it does
Stroke Range Min / MaxSets the lower and upper limits of travel, between 0% and 100%.
Range ExtenderAmplifies or reduces L0 movement around the 50% centre, before the final stroke range is applied.
Inverse StrokeFlips the script's position values before they are sent to the device.
Amplitude setting behavior v0.6.0Chooses whether this is remembered per script or shared across all media.
Centre-preserving range v0.6.0For centre-based axes such as rotation, narrows the span while holding the centre.
Starting out

Start narrow and widen it as you get used to the motion. Pair it with a speed limit to be safer still. → Safety and E-Stop

Handling empty stretches#

Options for scripts with long passages that contain no movement.

  • Fill gaps — fills the empty stretch with generated motion.
  • Automatic skipping — jumps past empty stretches. You can add a delay so it waits a moment instead of skipping instantly.
  • Sparse-script handling — smooths scripts whose points are far apart.

When there is no script at all — random stroke#

Motion can be generated for video that has no script. The presets keep the base tease pattern and the stronger pattern separate.

Generated motion offers smoothing at Off, Light, Balanced or Strong. Direction changes ride an acceleration curve instead of snapping, which reads far more naturally.

Generating a script from video# Experimental

Since v0.4.0 the motion in a video can be analysed into a funscript and saved beside the media. The analysis needs an external FFmpeg executable. → FFmpeg playback

Note

Motion analysis is experimental. Quality varies a lot by source, and the result may need hand-editing.

Multi-axis scripts#

Scripts that drive several axes at once are supported in three shapes.

  • One file holding its axes in axes[]
  • One file holding its axes in channels{}
  • A separate file per axis (for example video.L0.funscript, video.R0.funscript)

Since v0.6.0 you can replace the script source for a single axis. You might keep a multi-axis bundle but swap only its L0 for a different file. Axis source linking — deriving one axis from another — is supported too (for example L0 → R0).

For seeing a multi-axis script on screen, go to Timeline and heatmap.

Inspecting a script#

When a script behaves oddly, there is a view that shows exactly what values are arriving.

Timeline and heatmap

Two ways to see a script. The timeline shows this moment; the heatmap shows the whole file.

Timeline TL#

A live graph that scrolls with the playhead. Toggle it with TL on the playback bar.

Choosing axes

Open a multi-axis script and an AXES row appears above the timeline.

  • All — overlays every axis at once.
  • Axis buttons (L0, L1, R0, R1 …) — toggle each one. The number beside a button is that axis's current value.
  • Double-click — solos that axis and hides the rest. Handy for studying one axis closely.

Resizing

Drag the divider between the video and the timeline to change its height. With many axes, giving it more room helps a lot.

Heatmap HM#

Compresses the whole file into a single horizontal band. Colour means speed — green is slow, and it runs through yellow to red as it gets faster.

It tells you where the intense passages are before you play, which makes jumping to the part you want easy.

Note

Heatmaps are not drawn in the library list or on cards. They appear only during playback.

Timeline settings#

Settings → Timeline lets you adjust:

  • Contrast — draw the graph heavier or lighter
  • Speed colouring on or off
  • Default height

Audio and subtitles

Everything about sound and subtitles: playing audio files, boosting volume, loading subtitles and picking embedded tracks.

Playing audio files#

Audio such as MP3 or FLAC plays with a script attached exactly as video does. With no picture to show, it displays cover art instead.

Cover art is looked for in this order.

  • An image embedded in the audio file's metadata
  • An image file in the same work folder

150% volume boost# Experimental

For quiet recordings, volume can go up to 150%. A peak limiter runs alongside it to stop sudden spikes.

Careful

If you are wearing earphones, turn the volume down before switching the boost on.

Subtitles#

External subtitle files

.srt, .vtt and .txt are supported. A file named to match the video is found and attached automatically. If it is not, you can load one by hand.

Embedded subtitles

Text subtitle tracks inside the video file can be used too. Pick one from the AV button — but an external FFmpeg must be installed.

Subtitle kindSupported
SRT, ASS/SSA, WebVTT, mov_textYes — these are text-based tracks.
PGS and DVD subtitlesListed, but cannot be shown. They are image-based, and are not rendered.

Choosing an audio track#

For files carrying audio in several languages, pick the track from the AV button. This needs an external FFmpeg as well. → FFmpeg playback

VR and 360° video

Open a VR180 or 360° video and it looks stretched, or splits into two images. Tell it which projection to use and it renders properly. v0.6.0

Supported projections#

ProjectionWhat kind of video
360° equirectangularFilmed in every direction. Laid flat, it looks like a world map.
VR180 equirectangularOnly the forward 180 degrees. The most common form of VR video.
180° equidistant fisheyeFilmed as a circle that bulges at the centre.

Choosing the source layout#

Even within one projection, the two eyes can be packed in different ways.

  • Mono — a single image fills the frame.
  • Side-by-side (SBS) — one eye on the left, one on the right. Leave this unset and you see two images.
  • Top-and-bottom — one eye above, one below.

For SBS and top-and-bottom sources you can choose which eye to watch.

Looking around#

  • Drag — pull with the mouse to turn your view.
  • Zoom — pull in or push out to change the field of view.
Limits worth knowing
  • On the desktop, SBS and top-and-bottom sources show one eye at a time.
  • Stereoscopic WebXR output to a headset is not supported.
  • Stitching dual-fisheye 360° footage and lens-specific fisheye calibration are not included.
  • Video a projection cannot be applied to falls back to flat playback automatically. Nothing breaks.

The Handy

The Handy works over the internet: the script is uploaded to a server and playback time is synchronised. That means connection quality is felt directly.

Connecting#

  1. Find your connection key

    Read the Connection Key from the device's own display or from its app.

  2. Enter it in Settings → Device

    In Settings → Device, choose The Handy and paste the connection key.

  3. Confirm the connection

    The status changes once connected. Start a video and the script uploads and synchronises on its own.

Sync and time offset#

The Handy uses API v2. On playback it uploads the script and synchronises position against the server clock.

Start playing as soon as upload finishes

Switch on Auto Play After Handy Sync in Settings → Playback and playback begins the moment the upload and HSSP sync complete. No more waiting for sync and then reaching for play.

If the motion runs slightly early or late across the board, correct it with the time offset. If only one video is out, the script is the likelier cause — use the script offset instead.

Network diagnostics#

Settings → Handy Network Diagnostics measures your connection quality directly. If the motion keeps stuttering or lagging, start here.

SettingWhat it means
Median latencyRound-trip time under normal conditions. Lower is better.
P95 latencyThe latency of the slowest 5%. A high figure means occasional large spikes.
JitterHow much the latency varies. The higher it is, the less stable sync becomes.
Success rateThe proportion of requests that completed properly.
Server clock offsetThe difference between your machine's clock and the server's.
Sharing the results

The results can be copied and attached to a support request, which makes describing the problem far easier.

Compatibility mode#

There is a compatibility mode for older or slower-responding hardware. If the default settings behave erratically, try switching it on.

Intiface / Buttplug

Intiface is relay software that brings devices from many makers under one protocol. Since v0.6.0 ScriptPlayer+ has a dedicated workspace for it, so there is no separate window to juggle.

Two ways to connect#

Built-in engine

Uses the lightweight engine inside ScriptPlayer+. Nothing else to install, so it is the simplest route.

External Intiface Central

Connects to an Intiface Central you already run. It reaches more devices and more settings.

Connecting#

The Intiface icon on the left rail opens the Intiface Device Manager. Across the top it shows four steps — 1 Connect → 2 Find device → 3 Configure → 4 Playback — along with where you are and what to do next.

  1. Connect — choose how

    Pick Built-in engine or External Central. The built-in engine shows its address (ws://127.0.0.1:…); for external you enter the address to reach.

  2. Find device — scan

    Starting a scan looks for Bluetooth, HID and any configured serial devices. Keep the device powered on and ready to pair while it runs. You can select several at once.

  3. Configure — output mapping

    Under Output mapping, choose a device and map each usable feature to a script axis.

  4. Playback

    Play a video and output goes out on the axes you mapped. Battery level is shown here too.

The rail icon also reports state as idle, busy, connected or error.

Feature mapping#

Buttplug devices expose three kinds of feature. Each can be attached to the axis you want.

  • Linear — back-and-forth travel. Usually mapped to L0.
  • Rotate — rotation. Usually mapped to R0.
  • Scalar — anything expressed as a single magnitude, such as vibration strength.

If you need an axis the script does not contain, axis source linking can derive it from another. For instance, driving the R0 output from L0's movement.

Sharing with another app#

The built-in engine takes one client

The built-in Intiface engine accepts only one Buttplug client at a time. ScriptPlayer+ and another app cannot control it simultaneously.

That is what handoff is for. Press Allow FapTap / external app in the Intiface Device Manager and the engine keeps running while ScriptPlayer+ alone releases its connection. Another client such as FapTap can then attach to the same address, and once it disconnects ScriptPlayer+ reconnects.

Order matters

Launching the other app first and then trying to attach ScriptPlayer+ will fail. Release the connection from ScriptPlayer+ first, then connect the other app.

Per-device watchdogs#

With several devices connected, one that went slow or kept failing used to drag the others down with it. Since v0.6.0 each device has its own watchdog, so one bad device cannot hold up output to the rest.

What the Windows built-in engine covers#

The Windows built-in engine handles these connections.

  • Bluetooth LE
  • HID
  • One explicitly selected Bluetooth RFCOMM COM port — mapped as TCode v0.3 at 115200 baud.
Limits of that serial path

It exposes only the single linear-axis definition that FunOSR SR1 uses. For USB serial adapters, or the full multi-axis serial mapping of an SR6, use the FunOSR provider directly or an external Intiface Central.

FunOSR

FunOSR sends signals straight down a serial (COM) port. With no relay software in between, latency is lower and multi-axis mapping can be tuned finely.

Choosing a port#

In Settings → Device, choose FunOSR and select the COM port. Port detection improved in v0.6.0 and now suggests likely ports in this order.

  1. Ports explicitly identified as FunOSR
  2. CH340 / CH341 adapters
  3. USB identifier 1A86:7523
If the port briefly disappears

Even if the scan comes back empty at startup, your saved COM path is kept. Plugging the device in late does not wipe the setting.

Tuning the output#

Adjust these in Settings → Device.

SettingWhat it does
Update rateHow many commands are sent per second. Pushing it too high can actually destabilise things.
Axis mappingConnects script axes to the device's physical axes.
Motion smoothingSmooths the movement.
Custom speed limitCaps an axis's top speed in spm (full strokes per minute). You can also choose whether it follows the global limit or its own.
Pause / Stop BehaviorDecides what the device does when playback pauses, stops or changes media (for example Return home).
Home Return SpeedHow fast it returns home. Higher values move back more slowly.

Testing axes and centring#

You do not need to play a video to check an axis is wired correctly. In the Device Test Panel at the bottom of Settings → Device, the L0, V0, V1 and R0 buttons send a short command straight to that axis. Stop halts it at once, and the centre command returns it to the middle.

Checking for swapped axes

If pressing L0 makes it rotate, the axis mapping is wrong. Pressing each button in turn tells you immediately what is wired where.

To see which file a script actually came from and how it was read, switch on Show Script Debug Info. The player then displays the script path, its source, its axes and the stored offset.

SR1 options#

  • Bluetooth COM output — a 25 Hz cap plus TCode interpolation for smoother output. No keep-alive traffic while idle.
  • SR1 2.0 Twist quiet mode — limits the R0 rotation speed to cut motor noise.

Pause and resume#

Resuming after a delayed serial write could make the device lurch as it caught up all at once. v0.5.1 and v0.6.0 hardened this.

  • The resume transition now definitely completes once the configured start safety time has passed.
  • Catch-up progress is capped, so no large jump occurs.
  • Getting stuck in the safety transition and never returning to the live script is fixed.

Mobile and controller remote

Playback can be driven from a dedicated Bluetooth remote or from your phone — for play, pause and skipping to the next file without touching the keyboard.

Before connecting#

Android phone: Install the app using Get Android app in settings, then open its remote screen. Enable Bluetooth and grant the nearby-device permissions requested by the app. Turn on the BLE switch on the remote screen to make it available for connection, and note the displayed device name.

Dedicated remote: Turn on a device with supported firmware installed. If firmware installation is needed, first follow the instructions for that device in Open flasher in settings. Enable Bluetooth on the PC, then follow the pairing steps below.

Pairing#

  1. Open Settings

    Go to Settings → Mobile/Controller Remote.

  2. Connect

    On the PC, click Connect and select the name shown on your phone or your dedicated remote in the device picker.

  3. Enter the six-digit code

    Type the six-digit pairing code shown on the remote and press Pair.

Once paired, it reports status, firmware, battery and token. A remote you have paired once reconnects automatically thereafter.

Safety and E-Stop

If you are using a device, you must be able to stop it instantly. This page covers how, and the limits you can set in advance. If this is your first device, read this page first.

Global emergency stop (E-Stop)# v0.6.0

The Stop all devices button at the top right of the window. Regardless of which provider is currently selected, it sends a stop request to every connected device.

  • It quiesces playback and issues a stop to all of Handy, Intiface and FunOSR.
  • Stop requests are bounded, so nothing waits indefinitely.
  • A device that failed or timed out stays visible so you can retry it.

The button appears in the title bar and in fullscreen while a device is connected. You can turn it off under Show E-Stop button in Settings → Device.

Before you hide it

Even hidden, the stop control in the Intiface manager remains. But reaching it means changing screens first. Make sure you know where it is before hiding the button.

Limits to set in advance#

The best way to avoid a problem is to make sure it never moves hard in the first place.

Stroke range
Narrow the travel from STR on the playback bar. Start narrow. → Working with scripts
Custom speed limit
Caps top speed per axis in spm. Particularly useful with FunOSR. → FunOSR
Playback Start Safety
Instead of going full speed the instant playback starts, it eases to the script position over the time you set.
Centre-preserving range
For centre-based axes such as rotation, it holds the centre and reduces only the span.

One provider at a time#

Current limitation

Device output uses one active provider at a time. Driving Handy and Intiface / FunOSR simultaneously is not supported yet.

When you switch provider, the new connection attaches after the old one has been torn down. v0.6.0 fixed a case where moving from FunOSR to Handy or Intiface could stall on that cleanup.

Habits worth keeping#

  • The first time you play a new script, keep the range narrow and see what the motion is like.
  • Check the heatmap for the red passages ahead of time. → Timeline and heatmap
  • Let your hand learn where the E-Stop button is.
  • Never leave a device running unattended.

FFmpeg playback

Some features need an external FFmpeg executable. FFmpeg is not bundled with ScriptPlayer+, so you have to supply it. Experimental

When you need it#

ControlWhat FFmpeg does
Compatibility playbackPlays video in codecs the browser engine cannot open.
Embedded subtitlesExtracts text subtitle tracks from inside the video. → Audio and subtitles
Audio track selectionPicks one of several audio tracks.
Thumbnail fallbackBuilds thumbnails and hover previews for video Chromium cannot decode.
Motion analysisUsed when generating a script from video. → Working with scripts

How to supply it#

ScriptPlayer+ looks for FFmpeg in this order. Any one of them is enough.

  1. Install from Settings easiest

    A button in Settings installs it through your operating system's package manager — winget on Windows, Homebrew on macOS, a supported package manager on Linux. It runs only when you press it yourself.

  2. The FFMPEG_PATH environment variable

    Point this variable at the executable and it will be used.

  3. A common install location or the system PATH

    If FFmpeg is already installed, it is usually found automatically.

  4. Select it yourself

    Choose the FFmpeg executable in Settings. The sure route when auto-detection fails.

Choosing a compatibility mode#

Video Compatibility Mode in Settings → Playback sets how far it intervenes. Pick by symptom.

SymptomChoose
Plays fineAuto — steps in only when needed. The default.
Picture but no soundAudio compatibility — only the sound goes through FFmpeg.
Black picture, or will not open at allFull compatibility — the video goes through FFmpeg too.
Reopen after changing it

Changing the compatibility mode takes effect only after you close and reopen the video.

Why it is not bundled

ScriptPlayer+ release packages contain no FFmpeg executable and no FFmpeg source. Compatibility playback, thumbnail fallback and motion analysis use only an external executable.

Plugins

A way to add script sources yourself. No provider is bundled, recommended or enabled by default. You install one when you want one.

What a .funplugin is#

A .funplugin file is nothing but a JSON manifest. It carries information about where to look for scripts. It contains no executable code.

No code is executed

ScriptPlayer+ never runs plugin code inside the app. Because it only reads a data-only manifest, a plugin cannot take the app somewhere you did not ask for.

Installing and managing#

Managed from the Plugins icon on the left rail. Installation validates the following.

  • Manifest validation — strict checking that the format is correct.
  • Permissions — shows what it is asking for.
  • Signature — verified if the publisher supplied one. (Optional.)
  • Trust information — surfaces all of the above so you can see it.

Downloaded scripts#

Scripts fetched by a plugin are saved to your configured script folder, or to a folder the app manages if you have not set one. When a download finishes it is applied to the current media immediately.

Concurrent downloads each show their own progress.

Resetting#

The full reset on the Recovery tab clears more than settings: cached durations, stroke ranges, and the player, library, workspace, recent-media and sidebar state go with it.

Careful

A reset also discards the per-media offsets and stroke ranges you tuned. Your actual files are not touched.

Troubleshooting

Common symptoms and the order to check things. Work down from the top.

Installing and launching#

Windows shows a “protected your PC” warning

That is SmartScreen reacting to the Windows packages not being Authenticode signed. Click More info → Run anyway to install.

The app will not open on macOS

Press “Open Anyway” in System Settings → Privacy & Security. Also check that you are on macOS Monterey 12 or newer.

It will not run on Linux

On Ubuntu / Kubuntu 24.04 or newer, install the DEB package. The AppImage and archive packages cannot get around a system-wide user-namespace restriction, and ScriptPlayer+ will not launch itself with --no-sandbox.

Playback#

The video will not open, or I only get sound

  1. Check the extension is on the supported list. → Supported files
  2. The container may be right but the codec different. Supply FFmpeg and turn on compatibility playback.
  3. If that still fails, open it in an external player.

My VR video shows as two images

It is a side-by-side (SBS) source being played flat. Set the projection to VR180 equirectangular and the source layout to side-by-side. → VR and 360° video

Thumbnails are not being generated

Chromium cannot decode that video. With FFmpeg available, thumbnails are built by the fallback route instead.

Scripts#

My script is not detected

  1. Check the script sits in the same folder under the same name as the video.
  2. If you keep them apart, set the script folder from the sidebar.
  3. Press re-scan in the sidebar.
  4. If the names are completely different, use duration matching.

The motion runs ahead of or behind the video

Adjust the script offset using +0ms on the playback bar. Increase it if movement is late; decrease it if early. It is saved per script when possible, otherwise per media file. If all media has the same delay, also check the device time offset. → The Handy

It found one, but I want a different script

Swap it from the Script Variants panel in the sidebar. → Working with scripts

Devices#

The device does not move at all

  1. Confirm a script actually loaded. Can you see the timeline graph?
  2. Check the device status reads connected.
  3. Make sure the stroke range is not narrowed down close to zero. → Working with scripts
  4. Check you are not still in an E-Stop state. → Safety and E-Stop
  5. On FunOSR, use the live axis test to see whether the hardware responds at all.

The motion stutters or lags

  • The Handy — run the network diagnostics and look at latency and jitter. If they are poor, try a wired connection or a different network.
  • FunOSR — lower the update rate. Set too high, it becomes less stable, not more.
  • Intiface — if you have several devices, test with just one connected.

I cannot switch to another device

Output uses one provider at a time. Tearing down the previous connection can take a moment, so wait a few seconds and try again. → Safety and E-Stop

Another app cannot reach my Intiface device

The built-in Intiface engine accepts one client only. Hand ownership over with the handoff control in the Intiface manager. → Intiface / Buttplug

If none of that helps#

  1. Try a reset from Settings → Recovery. → Playback
  2. Check you are on the latest version. → Install
  3. Ask on GitHub Issues. For a device problem, copy the diagnostics and include them — it speeds things up a lot.
