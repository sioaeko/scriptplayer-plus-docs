ScriptPlayer+ 사용 설명서

ScriptPlayer+는 컴퓨터에 저장된 영상·음원을 펀스크립트와 함께 재생하고, 스크립트에 맞춰 The Handy·Intiface·FunOSR 장치를 제어하는 데스크톱 플레이어입니다. 이 설명서에서 설치 방법부터 기본 사용법, 장치 연결과 문제 해결까지 알아보세요.

설치하기

ScriptPlayer+는 Windows, macOS, Linux용 패키지를 GitHub Releases에서 내려받아 설치합니다. 처음 실행할 때 운영체제가 보안 경고를 띄우는 경우가 있는데, 아래에 해결 방법을 함께 적어 두었습니다.

내려받기#

모든 빌드는 GitHub Releases 최신 페이지에 올라옵니다. 사용하는 운영체제에 맞는 파일을 고르세요.

플랫폼패키지참고
Windows x64 설치 파일(.exe) 또는 포터블 .zip 설치 없이 쓰려면 포터블 ZIP을 받아 압축만 풀면 됩니다.
macOS x64 / arm64 .dmg 또는 .zip Apple Silicon과 Intel용 파일이 따로 있습니다. 본인 기기에 맞는 쪽을 받으세요.
Linux x64 .deb · AppImage · 압축 패키지 Ubuntu / Kubuntu 24.04 이상은 DEB 권장입니다.

Windows#

  1. 설치 파일 실행

    내려받은 .exe를 실행하면 먼저 사용권 계약(EULA)이 표시됩니다. 내용을 확인하고 동의하면 설치가 진행됩니다.

  2. SmartScreen 경고가 뜨면

    Windows 패키지에는 Authenticode 서명이 들어 있지 않습니다. 그래서 Microsoft Defender SmartScreen이 “Windows의 PC 보호” 같은 안내를 띄울 수 있습니다. 추가 정보 → 실행을 누르면 설치를 이어갈 수 있습니다.

  3. 포터블 ZIP을 쓸 경우

    압축을 푼 폴더 안의 실행 파일을 바로 실행합니다. 설정과 캐시는 사용자 폴더에 저장됩니다.

macOS#

최소 버전

v0.6.0부터 Electron 런타임이 올라가면서 필요한 최소 macOS 버전이 Big Sur 11에서 Monterey 12로 올라갔습니다. Big Sur에서는 v0.6 이상을 쓸 수 없습니다.

  1. DMG를 열고 앱을 옮기기

    .dmg를 연 뒤 ScriptPlayer+ 아이콘을 응용 프로그램 폴더로 끌어다 놓습니다.

  2. “열 수 없습니다” 경고가 뜨면

    Gatekeeper가 개발자를 확인하지 못했다는 경고를 띄울 수 있습니다. 시스템 설정 → 개인정보 보호 및 보안으로 들어가 아래쪽에 나타난 “확인 없이 열기” 버튼을 누르면 실행됩니다.

Linux#

Ubuntu / Kubuntu 24.04 이상은 DEB 패키지를 쓰는 것을 권장합니다. 이 버전들은 권한 없는 사용자 네임스페이스를 제한하는데, Chromium 샌드박스가 동작하려면 실행 파일 전용 AppArmor 프로필이 필요하고 그 프로필은 DEB 패키지에만 들어 있습니다.

  • DEB — AppArmor 프로필을 함께 설치합니다. 24.04 이상에서 가장 안전한 선택입니다.
  • AppImage — v0.6.0부터 정적 런타임으로 바뀌어 libfuse.so.2가 더 이상 필요 없습니다.
  • 압축 패키지 — 사용자 네임스페이스가 열려 있는 배포판에서 쓸 수 있습니다.
샌드박스를 끄지 않습니다

ScriptPlayer+는 시스템 차원의 네임스페이스 제한을 만났을 때 --no-sandbox로 자동 우회하지 않습니다. 포터블 AppImage나 압축 패키지가 실행되지 않는다면 DEB 패키지를 설치하세요.

업데이트#

새 버전이 나오면 앱 안에서 알림이 뜹니다. 알림에서 바로 내려받아 설치할 수 있고, 같은 버전으로 나온 핫픽스도 감지해 설치할 수 있습니다. 업데이트 확인 동작은 설정 → 일반에서 조정합니다.

빠르게 시작하기

설치를 끝냈다면 여기서부터입니다. 다섯 단계만 따라 하면 영상이 재생되고, 스크립트가 붙고, 장치가 움직입니다.

다섯 단계#

  1. 미디어가 있는 폴더를 엽니다

    왼쪽 위 Folder 버튼을 눌러 영상이 들어 있는 폴더를 고릅니다. 파일 하나만 빠르게 보고 싶다면 창 안으로 끌어다 놓아도(드래그 앤 드롭) 됩니다.

  2. 목록에서 영상을 고릅니다

    사이드바 파일 목록에서 파일을 클릭하면 바로 재생이 시작됩니다. 파일 이름 오른쪽에 초록색 문서 아이콘이 있으면 짝이 맞는 펀스크립트를 찾았다는 뜻입니다.

  3. 스크립트가 잘 붙었는지 확인합니다

    영상 아래 히트맵 띠와 타임라인 그래프가 보이면 스크립트가 정상적으로 읽힌 것입니다. 안 보인다면 재생바의 HM·TL 버튼을 눌러 켜 보세요.

  4. 장치를 연결합니다

    왼쪽 레일의 디바이스 아이콘을 눌러 사용하는 장치를 고르고 연결합니다. 장치별 자세한 설정은 The Handy, Intiface, FunOSR 문서를 참고하세요.

  5. 재생하고 세기를 맞춥니다

    Space로 재생합니다. 움직임이 너무 세거나 약하면 재생바의 STR에서 스트로크 범위를 줄이거나 늘립니다. 타이밍이 어긋나면 +0ms 버튼에서 오프셋을 조정합니다.

먼저 확인하면 좋은 것
  • 스크립트 파일은 보통 영상과 같은 폴더에 같은 이름으로 두면 자동으로 잡힙니다. (영상.mp4 ↔ 영상.funscript)
  • 스크립트를 따로 모아 둔 폴더가 있다면 설정에서 스크립트 폴더로 지정해 두세요.
  • 장치를 처음 쓸 때는 스트로크 범위를 좁게 잡고 시작하는 편이 안전합니다.

폴더 대신 라이브러리로 쓰기#

매번 폴더를 여는 대신, 자주 쓰는 폴더들을 라이브러리에 등록해 두면 썸네일 카드로 한눈에 볼 수 있습니다. 왼쪽 레일 맨 아래 라이브러리 아이콘에서 시작합니다. 자세한 내용은 라이브러리를 보세요.

사이드바#

파일 화면을 기준으로 위에서 아래로 이렇게 구성됩니다.

  • Folder — 미디어 폴더를 엽니다. 옆의 작은 버튼들로 스크립트 폴더 지정, 스크립트 불러오기·저장, 다시 검사를 합니다.
  • Recent Media — 최근에 연 파일 목록입니다. 항목 옆 ×로 하나씩, 휴지통 아이콘으로 전체를 지웁니다.
  • Filter files… — 파일 이름으로 걸러 냅니다. 오른쪽 숫자는 현재 보이는 파일 개수입니다.
  • Show multi-axis files only — 다축 스크립트가 있는 파일만 봅니다.
  • Show rated files only — 별점을 매긴 파일만 봅니다.
  • 정렬 — Path(경로) 기준을 비롯해 이름·별점·재생 시간·수정 시간으로 정렬하고, Asc/Desc로 방향을 바꿉니다.
  • Script Variants — 지금 미디어에 맞는 스크립트가 여러 개일 때 고르는 패널입니다. → 스크립트 다루기
  • 파일 목록 — 스크립트가 있는 파일에는 초록색 문서 아이콘이 붙습니다.

재생바 버튼 사전#

화면 맨 아래 줄입니다. 왼쪽은 재생 제어, 오른쪽은 화면·스크립트 관련 토글입니다. 짧은 영문 약자들은 다음과 같은 뜻입니다.

1x재생 속도 — 양옆의 − +로 배속을 조절합니다.
STR스트로크(Stroke) — 장치가 움직이는 범위를 그 자리에서 좁히거나 넓힙니다. 반전 토글도 여기 있습니다.
+0ms스크립트 오프셋 — 영상과 움직임의 시간 차를 밀거나 당깁니다. -60초 ~ +60초 범위로 조정할 수 있습니다.
AB구간 반복 — A 지점과 B 지점을 찍어 그 사이만 반복 재생합니다.
반복 — 지금 재생 중인 파일 하나만 반복합니다. 다음 파일로 자동으로 넘어가는 건 Auto Next Play 설정입니다.
랜덤 재생 — 목록을 무작위 순서로 재생합니다.
EXT외부 플레이어(External) — mpv·VLC 같은 외부 플레이어로 이 파일을 엽니다. → 외부 플레이어
TL타임라인(Timeline) — 스크립트 그래프를 켜고 끕니다.
HM히트맵(Heatmap) — 영상 전체의 강약을 색 띠로 보여 줍니다.
AV오디오·자막 트랙 — 내장 오디오 트랙과 자막 트랙을 고릅니다. → 오디오와 자막
별점 — 재생 화면에서 바로 점수를 매깁니다. 라이브러리 정렬·필터에 쓰입니다.
FIT맞춤 — 영상 전체가 보이도록 화면에 맞춥니다. 검은 여백이 생길 수 있습니다.
FILL채움 — 여백 없이 화면을 채웁니다. 영상 일부가 잘릴 수 있습니다.
전체화면 — F 키와 같습니다.

라이브러리

파일이 많아지면 폴더를 하나씩 여는 게 번거로워집니다. 라이브러리는 자주 쓰는 폴더들을 등록해 두고 썸네일 카드로 한 번에 훑어볼 수 있게 해 줍니다.

여러 폴더 등록하기#

v0.6.0부터 이름을 붙인 라이브러리 폴더를 여러 개 등록할 수 있습니다. 설정 → 일반의 Library folders에서 관리합니다. 각 폴더는 독립적으로 다루어져서, 하나를 꺼도 나머지는 그대로 남습니다.

  • Add folder — 폴더를 추가합니다. 선택 창에서 여러 개를 한 번에 고를 수 있습니다.
  • 이름 — 경로 대신 Local Library, NAS Library처럼 알아보기 쉬운 이름을 붙입니다.
  • 토글 — 잠시 빼고 싶을 때 끕니다. 꺼 둔 폴더는 설정이 그대로 저장되고 검사 대상에서만 빠집니다.
  • 휴지통 — 등록만 해제할 뿐, 실제 파일은 지우지 않습니다.
스크립트 폴더도 여기서

AB 구간 반복#

영상의 특정 구간만 계속 돌려 보고 싶을 때 씁니다. 시작점(A)과 끝점(B)을 찍으면 그 사이만 반복됩니다.

  1. 반복하고 싶은 구간의 시작 위치에서 A 지점을 지정합니다.
  2. 구간의 끝 위치에서 B 지점을 지정합니다.
  3. 구간 반복이 시작됩니다. 편집기를 열면 지점을 정확한 값으로 다듬을 수 있습니다.

A·B 지정과 편집기 열기는 모두 단축키로 지정할 수 있습니다. (키보드 단축키)

화면 맞춤 — FIT과 FILL#

영상 비율과 창 비율이 다를 때 어느 쪽을 우선할지 고르는 버튼입니다.

  • FIT — 영상이 전부 보이게 맞춥니다. 위아래나 좌우에 검은 여백이 생길 수 있습니다.
  • FILL — 화면을 꽉 채웁니다. 영상 가장자리가 잘릴 수 있습니다.

전체화면#

F로 전체화면에 들어갑니다. 전체화면에서도 사이드바를 불러올 수 있어 파일을 바꾸려고 나올 필요가 없습니다.

v0.6.0부터 전체화면 컨트롤의 표시 방식을 설정에서 바꿀 수 있습니다.

  • 아래쪽에서만 나타나게 하기 — 화면 아무 데나 마우스를 움직여도 컨트롤이 뜨지 않게 합니다.
  • 배경 투명도 — 컨트롤 뒤 배경을 더 진하게 또는 옅게 합니다.
  • 세로 위치 — 컨트롤이 뜨는 높이를 조정합니다.

항상 위에 두기#

다른 창을 쓰면서도 재생 화면을 계속 보고 싶을 때, 창을 항상 맨 앞에 고정할 수 있습니다.

되돌리기 · 복구#

설정을 이것저것 만지다 꼬였다면 설정 → 복구에서 초기 상태로 되돌릴 수 있습니다. 전체 초기화를 하면 캐시된 재생 시간, 스트로크 범위, 플레이어·라이브러리·작업 공간·최근 미디어·사이드바 상태가 함께 정리됩니다.

스크립트 다루기

스크립트가 자동으로 안 잡히거나, 잡혔는데 타이밍이 안 맞거나, 움직임이 너무 셀 때 어디를 만져야 하는지 정리했습니다. 이 문서 하나면 스크립트 관련 문제는 대부분 해결됩니다.

스크립트는 어떻게 찾아지나#

ScriptPlayer+는 다음 순서로 짝이 맞는 스크립트를 찾습니다.

  1. 같은 폴더의 같은 이름

    가장 확실한 방법입니다. 영상.mp4 옆에 영상.funscript를 두면 바로 잡힙니다.

  2. 지정한 스크립트 폴더

    스크립트를 따로 모아 뒀다면 설정 → 일반 → Script Storage Folder에서 그 폴더를 지정합니다. (사이드바 Folder 옆의 작은 버튼으로도 지정할 수 있습니다.) 이후 그 폴더도 함께 검사합니다.

  3. 라이브러리가 수집한 스크립트

    등록해 둔 라이브러리 폴더들이 색인해 놓은 스크립트도 후보에 들어갑니다.

  4. 후보가 하나뿐이면 자동 선택

    이름이 정확히 같지 않아도, 명확하게 하나로 좁혀지면 자동으로 골라 줍니다.

스크립트 변형 패널#

같은 영상에 맞는 스크립트가 여러 개일 때가 있습니다. Soft처럼 괄호로 라벨이 붙은 변형본이 대표적입니다. 이럴 때 사이드바의 Script Variants 패널에서 재생을 멈추지 않고 바로 바꿔 낄 수 있습니다.

재생 시간으로 찾기#

이름이 전혀 다른데 내용은 맞는 스크립트를 찾아야 할 때가 있습니다. v0.6.0에 들어온 재생 시간 기반 검색은 스크립트 타임라인의 길이가 영상 길이와 얼마나 비슷한지로 후보의 순위를 매깁니다.

  • 영상이 있는 폴더, 지정한 스크립트 폴더, 라이브러리가 색인한 스크립트를 모두 후보로 봅니다.
  • 길이가 비슷한 순서로 정렬해 보여 주므로, 위쪽 후보부터 시도하면 됩니다.

타이밍이 안 맞을 때 — 스크립트 오프셋#

양수(+)는 움직임을 앞당기고, 음수(-)는 늦춥니다. 움직임이 영상보다 약 0.2초 늦으면 현재 값에 0.2초를 더하고, 약 0.2초 빠르면 0.2초를 빼 보세요. 입력란은 초 단위이며 0.2초 = 200ms입니다.

영상보다 움직임이 조금 빠르거나 느릴 때 씁니다. 재생바의 +0ms 버튼을 눌러 조정합니다.

  • 범위는 -60초부터 +60초까지입니다.
  • 소수점 초 단위로 직접 입력할 수 있고, 미세 조정 버튼으로 조금씩 옮길 수도 있습니다.
  • 오프셋은 가능하면 스크립트별로, 그렇지 않으면 미디어별로 저장됩니다. 같은 스크립트를 다시 사용할 때 저장된 보정값이 적용될 수 있습니다.
  • 늘리기·줄이기·초기화 모두 단축키로 지정할 수 있습니다.
맞추는 요령

눈에 띄는 동작이 있는 지점으로 이동해 두고, 재생하면서 오프셋을 조금씩 옮겨 보세요. 타임라인 그래프의 봉우리와 화면 속 움직임이 겹치는 지점이 정답입니다.

빈 구간 다루기#

스크립트에 움직임이 없는 긴 구간이 있을 때 쓰는 옵션들입니다.

  • 갭 채우기(Fill gaps) — 빈 구간을 만들어 낸 움직임으로 채웁니다.
  • 자동 스킵 — 빈 구간을 건너뜁니다. 바로 넘기지 않고 잠시 기다렸다가 넘기도록 지연을 줄 수 있습니다.
  • 희소 스크립트 보정 — 점이 드문드문한 스크립트를 부드럽게 다듬습니다.

스크립트가 아예 없을 때 — 랜덤 스트로크#

스크립트가 없는 영상에서도 움직임을 만들어 낼 수 있습니다. 프리셋은 기본 애태우기 패턴과 더 강한 패턴이 구분되어 있습니다.

생성된 움직임은 부드럽기(스무딩)를 Off · Light · Balanced · Strong 중에서 고를 수 있습니다. 방향이 갑자기 꺾이지 않고 가속·감속 곡선을 타므로 훨씬 자연스럽습니다.

영상에서 스크립트 만들기# 실험 기능

v0.4.0부터 영상의 움직임을 분석해 펀스크립트를 만들고, 미디어 옆에 저장할 수 있습니다. 분석에는 외부 FFmpeg 실행 파일이 필요합니다. → FFmpeg 호환 재생

참고

모션 분석은 실험 기능입니다. 결과 품질은 영상에 따라 크게 달라지며, 만들어진 스크립트는 손으로 다듬어야 할 수 있습니다.

다축 스크립트#

여러 축을 동시에 쓰는 스크립트는 다음 세 가지 형태를 지원합니다.

  • 한 파일 안에 axes[]로 축을 담은 형식
  • 한 파일 안에 channels{}로 축을 담은 형식
  • 축마다 파일이 따로 있는 형식 (예: 영상.L0.funscript, 영상.R0.funscript)

v0.6.0부터는 축별로 스크립트 소스를 바꿔 낄 수 있습니다. 예를 들어 다축 번들을 그대로 쓰면서 L0 축만 다른 파일로 교체할 수 있습니다. 한 축의 움직임을 다른 축에서 끌어오는 축 소스 연동도 지원합니다. (예: L0 → R0)

다축 스크립트를 화면에서 보는 방법은 타임라인과 히트맵에 있습니다.

스크립트 점검하기#

스크립트가 이상하게 동작할 때, 어떤 값이 들어오고 있는지 확인할 수 있는 화면이 있습니다.

타임라인과 히트맵

스크립트를 눈으로 확인하는 두 가지 방법입니다. 타임라인은 지금 이 순간을, 히트맵은 영상 전체를 보여 줍니다.

타임라인 TL#

재생 위치를 따라 흐르는 실시간 그래프입니다. 재생바의 TL 버튼으로 켜고 끕니다.

축 고르기

다축 스크립트를 열면 타임라인 위에 AXES 줄이 나타납니다.

  • All — 모든 축을 한 번에 겹쳐 봅니다.
  • 축 버튼(L0, L1, R0, R1 …) — 눌러서 개별로 켜고 끕니다. 버튼 옆 숫자는 지금 그 축의 값입니다.
  • 더블클릭 — 그 축만 남기고 나머지를 숨깁니다. 한 축만 자세히 볼 때 편합니다.

높이 조절

영상과 타임라인 사이 경계를 위아래로 끌면 타임라인 높이가 바뀝니다. 축이 많을 때 넓게 펴 두면 훨씬 보기 좋습니다.

히트맵 HM#

영상 전체를 하나의 가로 띠로 압축해 보여 줍니다. 색이 속도를 뜻합니다 — 초록 쪽이 느리고, 노랑을 지나 빨강으로 갈수록 빠릅니다.

어디가 격한 구간인지 재생하기 전에 알 수 있어서, 원하는 지점으로 바로 건너뛸 때 유용합니다.

참고

라이브러리 목록과 카드에는 히트맵이 표시되지 않습니다. 히트맵은 재생 화면에서만 볼 수 있습니다.

타임라인 설정#

VR · 360 영상

VR180이나 360도 영상을 열면 화면이 이상하게 늘어나거나 두 개로 갈라져 보입니다. 투영 방식을 지정해 주면 정상적으로 볼 수 있습니다. v0.6.0

지원하는 투영 방식#

방식어떤 영상인가
360° 등장방형
(Equirectangular)		사방이 다 찍힌 전방위 영상입니다. 펼쳐 놓으면 세계지도처럼 보입니다.
VR180 등장방형앞쪽 180도만 찍힌 영상입니다. VR 영상에서 가장 흔합니다.
180° 등거리 어안
(Fisheye)		가운데가 볼록한 원형으로 찍힌 영상입니다.

원본 배치 고르기#

같은 투영 방식이라도 두 눈 영상이 어떻게 담겨 있는지가 다릅니다.

  • 모노(Mono) — 한 화면에 하나의 영상만 들어 있습니다.
  • 좌우 분할(SBS) — 왼쪽·오른쪽에 각각 한 눈씩 들어 있습니다. 지정하지 않으면 두 개로 갈라져 보입니다.
  • 상하 분할(Top-and-Bottom) — 위·아래에 각각 한 눈씩 들어 있습니다.

SBS나 상하 분할 영상은 어느 쪽 눈을 볼지 고를 수 있습니다.

보는 방법#

  • 드래그 — 마우스로 끌어 시점을 돌립니다.
  • 확대 / 축소 — 화면을 당기거나 밀어 시야각을 조절합니다.
알아 두면 좋은 한계
  • 데스크톱 화면에서는 SBS·상하 분할 영상의 한쪽 눈만 표시합니다.
  • 헤드셋으로 보내는 WebXR 입체 출력은 지원하지 않습니다.
  • 듀얼 어안 360도 영상을 이어 붙이는 기능과 렌즈별 어안 보정은 들어 있지 않습니다.
  • 투영을 적용할 수 없는 영상은 자동으로 평면 재생으로 되돌아갑니다. 화면이 깨지지는 않습니다.

The Handy

The Handy는 인터넷을 거쳐 동작합니다. 스크립트를 서버에 올리고 재생 시각을 맞추는 방식이라, 연결 품질이 체감에 직접 영향을 줍니다.

연결하기#

  1. 연결 키 확인

    The Handy 기기 화면 또는 앱에서 연결 키(Connection Key)를 확인합니다.

  2. 설정 → 디바이스에 입력

    ScriptPlayer+의 설정 → 디바이스에서 The Handy를 고르고 연결 키를 넣습니다.

  3. 연결 확인

    연결되면 상태 표시가 바뀝니다. 영상을 재생하면 스크립트가 자동으로 올라가고 동기화됩니다.

동기화와 시간 오프셋#

The Handy는 API v2로 동작합니다. 재생을 시작하면 스크립트를 업로드하고 서버 시계에 맞춰 재생 위치를 동기화합니다.

업로드가 끝나면 자동으로 재생하기

설정 → 재생의 Auto Play After Handy Sync를 켜면, 업로드와 HSSP 동기화가 끝나는 즉시 재생이 시작됩니다. 매번 동기화가 끝나기를 기다렸다가 재생 버튼을 누를 필요가 없습니다.

전체적으로 움직임이 조금 이르거나 늦다면 시간 오프셋으로 보정합니다. 특정 영상만 어긋난다면 그건 스크립트 쪽 문제일 가능성이 크니 스크립트 오프셋을 대신 쓰세요.

네트워크 진단#

설정 → Handy 네트워크 진단에서 연결 품질을 직접 측정할 수 있습니다. 움직임이 자꾸 끊기거나 밀린다면 여기서부터 확인하세요.

항목의미
중간값 지연보통 상태에서의 왕복 시간입니다. 낮을수록 좋습니다.
P95 지연느린 쪽 5%의 지연입니다. 이 값이 크면 가끔씩 크게 튄다는 뜻입니다.
지터지연이 얼마나 들쭉날쭉한지입니다. 클수록 동기화가 불안정합니다.
성공률요청이 제대로 오간 비율입니다.
서버 시계 오차내 컴퓨터 시계와 서버 시계의 차이입니다.

진단 결과는 복사해서 문의할 때 첨부할 수 있습니다. 문제 상황을 설명하기 훨씬 수월해집니다.

호환 모드#

구형 하드웨어나 반응이 느린 기기를 위한 호환 모드가 있습니다. 기본 설정으로 동작이 불안정하면 이 모드를 켜 보세요.

Intiface / Buttplug

Intiface는 여러 제조사의 장치를 하나의 규격으로 묶어 주는 중계 소프트웨어입니다. v0.6.0부터 ScriptPlayer+ 안에 전용 작업 공간이 생겨, 별도 창을 오가지 않고 다룰 수 있습니다.

두 가지 연결 방식#

내장 엔진

ScriptPlayer+ 안에 들어 있는 경량 엔진을 씁니다. 따로 설치할 게 없어 가장 간편합니다.

외부 Intiface Central

이미 쓰고 있는 Intiface Central에 연결합니다. 더 많은 장치와 설정을 다룰 수 있습니다.

연결하기#

왼쪽 레일의 Intiface 아이콘을 누르면 Intiface Device Manager가 열립니다. 화면 위쪽에 1 Connect → 2 Find device → 3 Configure → 4 Playback 네 단계가 표시되고, 지금 어느 단계인지와 다음에 무엇을 할지를 함께 알려 줍니다.

  1. Connect — 연결 방식 고르기

    Built-in engine과 External Central 중 하나를 고릅니다. 내장 엔진을 쓰면 주소(ws://127.0.0.1:…)가 표시되고, 외부를 고르면 접속할 주소를 넣습니다.

  2. Find device — 장치 검색

    스캔을 시작하면 Bluetooth · HID · 설정된 시리얼 장치를 찾습니다. 장치 전원을 켜고 페어링 대기 상태로 둔 채 기다리세요. 여러 장치를 동시에 선택할 수 있습니다.

  3. Configure — 출력 매핑

    Output mapping에서 장치를 고르고, 쓸 수 있는 기능을 각각 어느 스크립트 축에 붙일지 지정합니다.

  4. Playback — 재생

    영상을 재생하면 매핑한 축으로 출력이 나갑니다. 배터리 잔량도 이 화면에서 확인할 수 있습니다.

연결 상태는 레일 아이콘에도 연결 안 됨 · 작업 중 · 연결됨 · 오류로 표시됩니다.

기능 매핑#

Buttplug 장치는 기능이 세 갈래로 나뉩니다. 각각을 원하는 축에 붙일 수 있습니다.

  • 선형(Linear) — 앞뒤로 움직이는 동작. 보통 L0 축을 연결합니다.
  • 회전(Rotate) — 돌아가는 동작. 보통 R0 축을 연결합니다.
  • 스칼라(Scalar) — 진동 세기처럼 크기 하나로 표현되는 동작입니다.

스크립트에 없는 축이 필요하다면 축 소스 연동으로 다른 축에서 값을 끌어올 수 있습니다. 예를 들어 L0의 움직임을 R0 출력으로 쓰는 식입니다.

다른 앱과 함께 쓰기#

내장 엔진은 한 번에 하나만

내장 Intiface 엔진은 Buttplug 클라이언트를 하나만 받습니다. ScriptPlayer+와 다른 앱이 동시에 제어할 수 없습니다.

그래서 핸드오프 기능이 있습니다. Intiface Device Manager의 Allow FapTap / external app 버튼을 누르면, 엔진은 계속 돌아가는 상태로 두고 ScriptPlayer+만 연결을 놓아 줍니다. 그 사이에 FapTap 같은 다른 클라이언트가 같은 주소로 붙을 수 있고, 그 앱이 끊으면 ScriptPlayer+가 다시 연결합니다.

순서가 중요합니다

다른 앱을 먼저 띄우고 나서 ScriptPlayer+를 붙이려 하면 실패합니다. ScriptPlayer+에서 먼저 연결을 놓아 준 다음 다른 앱을 연결하세요.

장치별 워치독#

장치를 여러 개 쓸 때, 한 장치가 느려지거나 계속 실패하면 다른 장치까지 끌려가 멈추는 일이 있었습니다. v0.6.0부터는 장치마다 독립적인 워치독이 붙어, 문제가 있는 장치 하나 때문에 나머지 출력이 막히지 않습니다.

Windows 내장 엔진의 범위#

Windows용 내장 엔진이 다룰 수 있는 연결은 다음과 같습니다.

  • Bluetooth LE
  • HID
  • 명시적으로 지정한 Bluetooth RFCOMM COM 포트 하나 — TCode v0.3, 115200 baud로 매핑됩니다.
이 시리얼 경로의 한계

이 경로는 FunOSR SR1이 쓰는 단일 선형 축 정의만 노출합니다. USB 시리얼 어댑터나 SR6의 전체 다축 시리얼 매핑이 필요하면 FunOSR 공급자를 직접 쓰거나 외부 Intiface Central을 쓰세요.

FunOSR

FunOSR는 시리얼(COM) 포트로 직접 신호를 보내는 방식입니다. 중계 소프트웨어를 거치지 않아 지연이 적고, 다축 매핑을 세밀하게 다룰 수 있습니다.

포트 고르기#

설정 → 디바이스에서 FunOSR를 고르고 COM 포트를 지정합니다. v0.6.0부터 포트 인식이 개선되어, 다음 순서로 알맞은 포트를 먼저 제안합니다.

  1. FunOSR로 명확히 식별되는 포트
  2. CH340 / CH341 어댑터
  3. USB 식별자 1A86:7523
포트가 잠깐 안 보여도

시작할 때 검색 결과가 비어 있어도 저장해 둔 COM 경로는 유지됩니다. 장치를 늦게 꽂았을 때 설정이 날아가지 않습니다.

축 테스트와 중앙 정렬#

축이 제대로 연결됐는지 확인하려고 영상을 재생할 필요는 없습니다. 설정 → 디바이스 맨 아래의 Device Test Panel에서 L0 · V0 · V1 · R0 버튼을 눌러 해당 축에 짧은 명령을 직접 보내 볼 수 있습니다. Stop으로 즉시 멈추고, 중앙 위치 명령으로 가운데로 되돌립니다.

축 순서가 뒤바뀌었는지 확인할 때

L0를 눌렀는데 회전이 움직이면 축 매핑이 잘못된 것입니다. 이 패널로 하나씩 눌러 보면 어느 축이 어디에 연결됐는지 바로 알 수 있습니다.

스크립트가 실제로 어떤 파일에서 어떻게 읽혔는지 확인하려면 Show Script Debug Info를 켜세요. 재생 화면에 스크립트 경로 · 출처 · 축 목록 · 저장된 오프셋이 표시됩니다.

SR1 관련 옵션#

  • Bluetooth COM 출력 — 25Hz 상한과 TCode 보간을 적용해 더 매끄럽게 내보냅니다. 쉴 때는 유지 신호를 보내지 않습니다.
  • SR1 2.0 Twist 조용 모드 — R0 회전 속도 상한을 조절해 소음을 줄입니다.

일시정지와 재개#

시리얼 전송이 지연된 뒤 재생을 재개하면, 밀린 만큼을 한꺼번에 따라잡느라 장치가 크게 튈 수 있습니다. v0.5.1과 v0.6.0에서 이 부분이 보강되었습니다.

  • 재개 전환은 설정한 안전 시작 시간이 지나면 확실히 끝납니다.
  • 밀린 진행량은 상한을 두고 따라잡으므로 큰 점프가 생기지 않습니다.
  • 안전 전환 상태에 갇혀 스크립트로 돌아오지 못하던 문제가 해결되었습니다.

모바일 · 컨트롤러 리모트

연결 전에 준비하기#

Android 휴대폰: 설정의 Get Android app으로 앱을 설치한 뒤 휴대폰에서 리모트 화면을 엽니다. Bluetooth를 켜고 앱이 요청하는 근처 기기 권한을 허용하세요. 리모트 화면의 BLE 스위치를 켜서 연결 대기 상태로 두고, 표시된 기기 이름을 확인합니다.

전용 리모컨: 지원되는 펌웨어가 설치된 기기의 전원을 켭니다. 펌웨어 설치가 필요하면 설정의 Open flasher에서 해당 기기용 안내를 먼저 따르세요. PC에서도 Bluetooth를 켠 뒤 아래 페어링 절차를 진행합니다.

페어링하기#

  1. 설정 열기

    설정 → 모바일/컨트롤러 리모트로 들어갑니다.

    PC에서 Connect를 누르고, 기기 선택 창에서 휴대폰 화면에 표시된 이름 또는 전용 리모컨을 선택합니다.

전역 비상 정지 (E-Stop)# v0.6.0

창 오른쪽 위의 Stop all devices 버튼입니다. 지금 어떤 공급자를 쓰고 있는지와 상관없이, 연결된 모든 장치에 정지 요청을 보냅니다.

  • 재생을 멈추고, Handy · Intiface · FunOSR 모두에게 정지 명령을 보냅니다.
  • 정지 요청에는 제한 시간이 있어 무한정 기다리지 않습니다.
  • 실패하거나 시간이 초과된 장치는 목록에 남아 다시 시도할 수 있습니다.

이 버튼은 장치가 연결되어 있을 때 제목 표시줄과 전체화면에 나타납니다. 표시 여부는 설정 → 디바이스의 Show E-Stop button에서 끌 수 있습니다.

버튼을 숨기기 전에

숨겨 두더라도 Intiface 관리 화면의 정지 컨트롤은 그대로 남아 있습니다. 하지만 그쪽은 화면을 한 번 옮겨야 닿습니다. 숨기기 전에 그 위치를 반드시 확인해 두세요.

준비하는 방법#

ScriptPlayer+는 다음 순서로 FFmpeg를 찾습니다. 어느 하나만 충족하면 됩니다.

  1. 설정에서 자동 설치 가장 쉬움

    설정 화면의 버튼으로 운영체제 패키지 관리자를 통해 설치할 수 있습니다. Windows는 winget, macOS는 Homebrew, Linux는 지원되는 패키지 관리자를 씁니다. 사용자가 직접 눌렀을 때만 실행됩니다.

  2. 환경 변수 FFMPEG_PATH

    실행 파일 경로를 이 환경 변수에 지정해 두면 그것을 씁니다.

  3. 일반 설치 경로 또는 시스템 PATH

    이미 FFmpeg가 설치되어 있다면 대개 자동으로 찾습니다.

  4. 직접 고르기

    설정에서 FFmpeg 실행 파일을 직접 지정합니다. 자동 검색이 실패했을 때 확실한 방법입니다.

호환 모드 고르기#

설정 → 재생의 Video Compatibility Mode에서 얼마나 개입할지 정합니다. 증상에 따라 고르세요.

증상고를 것
잘 재생됨Auto — 필요할 때만 알아서 개입합니다. 기본값입니다.
화면은 나오는데 소리가 안 남오디오 호환 모드 — 소리만 FFmpeg로 처리합니다.
화면이 검거나 아예 안 열림전체 호환 모드 — 영상까지 FFmpeg로 처리합니다.
바꾼 뒤에는 다시 열어야 합니다

호환 모드를 바꾸면 영상을 닫고 다시 열어야 적용됩니다.

패키지에 포함되지 않는 이유

ScriptPlayer+ 릴리스 패키지에는 FFmpeg 실행 파일이나 FFmpeg 소스가 들어 있지 않습니다. 호환 재생·썸네일 대체·모션 분석은 모두 외부 실행 파일만 사용합니다.

플러그인

스크립트 공급자를 직접 추가하는 기능입니다. 기본으로 포함되거나 추천되는 공급자는 하나도 없습니다. 필요할 때 직접 설치해서 씁니다.

.funplugin이란#

.funplugin 파일은 JSON 매니페스트일 뿐입니다. 어디에서 스크립트를 찾을지에 대한 정보만 담겨 있고, 실행 코드는 들어 있지 않습니다.

코드를 실행하지 않습니다

ScriptPlayer+는 플러그인의 코드를 앱 안에서 실행하지 않습니다. 데이터 전용 매니페스트만 읽기 때문에, 플러그인이 앱을 마음대로 조작할 수 없습니다.

설치와 관리#

왼쪽 레일의 플러그인 아이콘에서 관리합니다. 설치할 때 다음이 검증됩니다.

  • 매니페스트 검사 — 형식이 올바른지 엄격하게 확인합니다.
  • 권한 확인 — 무엇을 요구하는지 표시합니다.
  • 서명 — 게시자 서명이 있으면 확인합니다. (선택 사항)
  • 신뢰 정보 표시 — 위 결과를 사용자가 볼 수 있게 보여 줍니다.

내려받은 스크립트#

플러그인으로 받은 스크립트는 지정해 둔 스크립트 폴더에 저장됩니다. 지정하지 않았다면 앱이 관리하는 폴더에 저장됩니다. 내려받기가 끝나면 지금 재생 중인 미디어에 즉시 적용됩니다.

여러 개를 동시에 받을 때는 각각의 진행률이 따로 표시됩니다.

FFmpeg 실행 파일 경로는 설정 안에서 한 줄로 표시되며, 직접 고르거나 패키지 관리자로 설치할 수 있습니다. 자세한 내용은 FFmpeg 호환 재생에 있습니다.

초기화#

복구 탭의 전체 초기화는 설정뿐 아니라 캐시된 재생 시간, 스트로크 범위, 플레이어·라이브러리·작업 공간·최근 미디어·사이드바 상태까지 함께 정리합니다.

주의

초기화하면 미디어별로 맞춰 둔 오프셋과 스트로크 범위도 사라집니다. 실제 파일은 지워지지 않습니다.

지원 파일 형식

어떤 파일을 열 수 있는지 정리했습니다.

미디어#

종류확장자
영상mp4 · mkv · avi · webm · mov · wmv
오디오mp3 · wav · flac · m4a · aac · ogg · opus · wma
확장자가 맞아도 안 열릴 수 있습니다

컨테이너 확장자가 같아도 안에 든 코덱은 다를 수 있습니다. 재생이 안 되면 FFmpeg 호환 재생을 준비해 보세요.

스크립트#

형식설명
.funscript가장 일반적인 펀스크립트 형식입니다.
.json펀스크립트와 같은 구조의 JSON 파일입니다.
.csv표 형태로 저장된 스크립트입니다.

다축 번들

  • 한 파일에 axes[]로 축을 담은 형식
  • 한 파일에 channels{}로 축을 담은 형식
  • 축마다 파일이 나뉜 형식 — 예: 영상.L0.funscript, 영상.R0.funscript

자막#

종류지원
외부 자막 파일.srt · .vtt · .txt
내장 텍스트 자막SRT · ASS/SSA · WebVTT · mov_text — 외부 FFmpeg 필요
이미지 기반 자막PGS · DVD 자막은 목록에 보이지만 표시할 수 없습니다.

파일 이름 규칙#

자동 매칭이 가장 잘 되는 배치는 이렇습니다.

내 영상 폴더/
├─ 작품A.mp4
├─ 작품A.funscript          ← 자동으로 잡힙니다
├─ 작품A.srt                ← 자막도 자동으로 잡힙니다
├─ 작품B.mp4
├─ 작품B.L0.funscript       ← 다축: 선형 축
└─ 작품B.R0.funscript       ← 다축: 회전 축

이름이 다르더라도 재생 시간으로 찾기나 스크립트 변형 패널로 연결할 수 있습니다.

문제 해결

자주 나오는 증상과 확인 순서를 모았습니다. 위에서부터 차례로 시도해 보세요.

설치 · 실행#

Windows에서 “PC 보호” 경고가 뜹니다

Windows 패키지에 Authenticode 서명이 없어서 SmartScreen이 띄우는 안내입니다. 추가 정보 → 실행을 누르면 설치할 수 있습니다.

macOS에서 앱이 열리지 않습니다

시스템 설정 → 개인정보 보호 및 보안에서 “확인 없이 열기”를 누르세요. macOS Monterey 12 이상이 필요하다는 점도 확인해 주세요.

Linux에서 실행되지 않습니다

Ubuntu / Kubuntu 24.04 이상이라면 DEB 패키지를 설치하세요. AppImage와 압축 패키지는 시스템의 사용자 네임스페이스 제한을 우회하지 못하고, ScriptPlayer+는 --no-sandbox로 자동 실행하지 않습니다.

재생#

영상이 열리지 않거나 소리만 납니다

  1. 확장자는 지원 목록에 있는지 확인합니다. → 지원 파일 형식
  2. 컨테이너는 맞아도 코덱이 다를 수 있습니다. FFmpeg를 준비하고 호환 재생을 켜 보세요.
  3. 그래도 안 되면 외부 플레이어로 열어 봅니다.

VR 영상이 두 개로 갈라져 보입니다

좌우 분할(SBS) 영상인데 평면으로 재생되고 있는 것입니다. 투영 방식을 VR180 등장방형으로, 원본 배치를 좌우 분할로 지정하세요. → VR · 360 영상

썸네일이 안 만들어집니다

Chromium이 그 영상을 디코딩하지 못하는 경우입니다. FFmpeg가 있으면 대체 방식으로 썸네일을 만들어 줍니다.

스크립트#

스크립트가 자동으로 안 잡힙니다

  1. 스크립트가 영상과 같은 폴더에 같은 이름으로 있는지 확인합니다.
  2. 따로 모아 뒀다면 사이드바에서 스크립트 폴더를 지정합니다.
  3. 사이드바에서 다시 검사를 눌러 봅니다.
  4. 이름이 전혀 다르다면 재생 시간으로 찾기를 씁니다.

움직임이 영상보다 빠르거나 느립니다

재생바 +0ms에서 스크립트 오프셋을 조정하세요. 움직임이 늦으면 값을 늘리고, 빠르면 줄입니다. 보정값은 가능하면 스크립트별로, 그렇지 않으면 미디어별로 저장됩니다. 전체가 일정하게 밀린다면 장치 쪽 시간 오프셋도 확인하세요. → The Handy

잡히긴 했는데 다른 스크립트를 쓰고 싶습니다

사이드바의 Script Variants 패널에서 바꿔 낄 수 있습니다. → 스크립트 다루기

장치#

장치가 전혀 안 움직입니다

  1. 스크립트가 실제로 붙었는지 확인합니다. 타임라인 그래프가 보이나요?
  2. 장치 연결 상태가 연결됨인지 확인합니다.
  3. 스트로크 범위가 0에 가깝게 좁혀져 있지 않은지 확인합니다. → 스크립트 다루기
  4. 비상 정지를 눌러 둔 상태가 아닌지 확인합니다. → 안전과 비상 정지
  5. FunOSR라면 라이브 축 테스트로 장치 자체가 반응하는지 봅니다.

움직임이 끊기거나 밀립니다

  • The Handy — 네트워크 진단을 돌려 지연과 지터를 확인합니다. 값이 나쁘면 유선 연결이나 다른 네트워크를 시도하세요.
  • FunOSR — 업데이트 레이트를 낮춰 봅니다. 너무 높으면 오히려 불안정해집니다.
  • Intiface — 장치를 여러 개 쓰고 있다면 하나만 남기고 시험해 봅니다.

다른 장치로 바꿀 수 없습니다

출력은 한 번에 하나의 공급자만 사용합니다. 이전 연결이 정리되는 데 잠시 걸릴 수 있으니 몇 초 기다렸다가 다시 시도하세요. → 안전과 비상 정지

다른 앱이 Intiface 장치를 못 잡습니다

내장 Intiface 엔진은 클라이언트를 하나만 받습니다. Intiface 관리 화면의 핸드오프 컨트롤로 제어권을 넘겨주세요. → Intiface / Buttplug

그래도 안 될 때#

  1. 설정 → 복구에서 초기화를 시도합니다. → 재생 다루기
  2. 최신 버전인지 확인합니다. → 설치하기
  3. GitHub Issues에 문의합니다. 장치 문제라면 진단 정보를 복사해 함께 올리면 훨씬 빠릅니다.
